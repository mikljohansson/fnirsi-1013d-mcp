// Copy of Atlan4's "FPGA commands.txt" (D:\src\Fnirsi1013D\Verzia 1.xxx\FPGA for 1.xxx\), updated
// for fpga/al3/src/zaklad.v of fnirsi-1013d-mcp. Changes against Atlan4's file:
//  - 0x06 returns 0x15 0x3A (0x153A = 0x1539 with the ADC data captured through IOB registers at a per-core stage
//    (write 0x63, read 0x36 with outlier counters, write 0x64), B first by T/2 at every rate; 0x1539 = 0x1538 with the
//    read byte loaded on the falling edge of the MCU clock, the
//    start of the strobe, so it is settled on the pins before the MCU reads it; values, pointer advance and dummy strobe
//    unchanged; 0x1538 = 0x1537 with the encode timing fix and read 0x33; 0x1537 = 0x1536 with the
//    record-start and A/B-order fixes, no new command; 0x1536 = with
//    segments/averaging; 0x1535 = without segments/averaging, 0x1534 = decimation filter without the FIR,
//    0x1533 = EXT trigger only; Atlan4's 0x1532 AL3 design returns 0x15 0x32, his file still shows 0x14).
//  - 0x15 takes data[1:0]: 0 = CH1, 1 = CH2, 2 = EXT (calibration pin P133), 3 = reserved (acts as EXT).
//  - 0x28 (new read): external trigger status.
//  - 0x53, 0x54, 0x55 (new writes), 0x29 (new read): decimation filter (0x1534). With 0x53 = 0 (power-on)
//    the design behaves exactly as 0x1533.
//  - 0x56 (new write), 0x29 byte 0 bits 6/5: CIC compensation FIR (0x1535). With 0x56 = 0 (power-on) the
//    design behaves exactly as 0x1534.
//  - 0x57..0x5D (new writes), 0x2A..0x32 (new reads): segmented capture and hardware averaging (0x1536). With
//    0x57 = 0 (power-on) the design behaves exactly as 0x1535; 0x0A then reads as before.
//  - 0x33 (new read, 0x1538): encode self-check, 1 byte. Bit 0 sticky: a check failed since the last 0x01 = 1;
//    bit 1: the last write clock prediction was right; bits 3:2 = 01, encode convention 1 (B = write clock, A = its
//    complement, 1.25 ns later); bits 7:4 the last pin check {CH2 A, CH2 B, CH1 A, CH1 B}, 1 = right. A good arm
//    reads 0xF6. Write 0x33 (CH1 relays) is unchanged.
//  - 0x63, 0x64 (new writes), 0x36 (new read, 0x153A): ADC capture stage per core and the B-core reference edge
//    (0x63, 2 bytes; power-on 0x08E4 = CH1 A stage 4, CH1 B 4, CH2 A 3, CH2 B 4, B timed by its own encode), the
//    outlier threshold (0x64, power-on 8 codes) and the stages plus four 16-bit outlier counters (0x36, 10 bytes).
//    0x53 bits 3 / 4 read back but select nothing any more. Write 0x36 (CH2 relays) is unchanged. The legacy data
//    reach the memory 4 words later than on 0x1539 at 200 MSa/s (3 words at divided rates, 40 ns with K >= 1); EXT
//    is not delayed, so the EXT-to-data offset grows by that much (fpga/al3/README.md section 10).
//  - 0x5E, 0x5F, 0x60, 0x66 (new writes), 0x34, 0x37 (new reads), 0x1B (meaning changes), 0x153C C1
//    (docs/plans/fpga-0x153c.md sections 2, 3): trigger types pulse width / Nth edge / timeout on CH1, CH2 and EXT,
//    and the trigger hold-off on 0x1B (u32, 5 ns units; Atlan4 stored it and never used it, 0x153B and before). With
//    0x5E = 0 and 0x1B = 0 (power-on) the capture is cycle-identical to 0x153B. Write 0x34 / 0x37 (AC/DC relays)
//    are unchanged.
//  - 0x61, 0x62 (new writes), 0x35 (new read, 16 bytes; 0x153C): hardware counter with min / max (reciprocal frequency,
//    period, width and duty of CH1 / CH2 / EXT over a 10 ms / 100 ms / 1 s gate, the source's raw min and max over the
//    gate). With 0x61 = 0 (power-on) nothing runs; the counter never touches the capture. Write 0x35 (CH2 offset) is
//    unchanged (docs/plans/fpga-0x153c.md section 5, fpga/al3/README.md section 13).
//  - 0x6C, 0x6D, 0x6E, 0x6F (new writes), 0x39 (new read), 0x51 / 0x52 retired, 0x15 value 3 (0x153D D2, docs/plans/
//    fpga-0x153c.md section 7, fpga/al3/README.md section 15): the pulse pattern generator is the generator. Atlan4's
//    DDS is gone; 0x50 = 1 drives the calibration pin with the pattern's level (power-on: the idle level 0). The square
//    wave is a two-step continuous pattern; a step flagged mark is the capture's trigger source 3. 0x76 .. 0x7D (new
//    writes), 0x42 (new read): the pattern trigger engine, the capture trigger's layouts on its own qualifier.
//  - 0x0B, 0x0C, 0x1F high bytes: zaklad.v takes io_mcu_data[5:0] into [12:8] (bit 5 is dropped by the
//    13-bit register); this file showed [4:0].
// Multi-byte values are high byte first. Details: fpga/al3/README.md, section "Changes".

//================================ FPGA commands table ==================================
// Read timing (0x1539): every read byte below is loaded into o_mcu_data on the FALLING edge of i_mcu_clk (the start of
// the strobe; 0x1532..0x1538: the rising edge) and holds until the next strobe starts. The read pointer and mcu_state
// still advance on the rising edge, so the byte of a read strobe is the same as before; read the bus after raising the
// clock, as the firmware does.

//***************************************************************************************
//********************************** READING commands ***********************************
//***************************************************************************************

            8'h05: //Reading of the sampling system resets state
                    o_mcu_data[0] <= sample_system_state;
//---------------------------------------------------------------------------------------
            8'h06: //Reading of the FPGA version needs loading of high byte first
                  4'h0:
                    o_mcu_data <= 8'h15;
                  4'h1:
                    o_mcu_data <= 8'h3A;       //0x153A = AL3 with external trigger, decimation filter, FIR, segments, averaging,
                                               //         encode self-check, settled readout, staged ADC capture
            
            //When sampling finishes the writing is disabled. Enabled again with a reset.
            8'h0A: //Reading of the sampling done state
                    o_mcu_data[0] <= q_active ? q_done : ~sample_write_enable;
                    //0x1536: after an arm with 0x57 mode 1 or 2, bit0 = the whole run is done (all segments or
                    //all averages, or stopped); otherwise ~sample_write_enable as before

            8'h14: //Reading of the trigger address needs loading of high byte first
                   //Triggered: the word of the trigger (section below, +-1). Ended on the auto time-out or on 0x1A = 0
                   //written while the capture ran: 0x1532..0x153A pretrigger (record = ring 0 .. total - 1, spliced
                   //if the stop fell inside it); 0x153B W - total + pretrigger, W the address after the last word
                   //written, so 0x14 - pretrigger is the newest total words. Frozen with the write (0x153B).
                  4'h0:
                    o_mcu_data <= trigger_address[12:8];
                  4'h1:
                    o_mcu_data <= trigger_address[7:0];
            
            //This is not used in the software and is basically the same as command 0x0A
            //0x153B: no trigger is taken after the write has stopped, so bit0 describes the record (up to 0x153A an
            //edge after the stop set it)
            8'h18: //Reading of the sampling triggered state
                    o_mcu_data[0] <= sampling_triggered;
              
	    8'h1F //Loading two bytes of the data read address offset high byte first
                  4'h0:
		    sample_read_offset[12:8] <= io_mcu_data[5:0];
		  4'h1:
		    sample_read_offset[7:0] <= io_mcu_data;
            
            //0x20..0x23 read one byte of the 32-bit memory word and advance the read address by one word.
            //With K >= 1 (0x53) the word is { CH2[15:0], CH1[15:0] }: 0x20 = CH1 low byte, 0x21 = CH1 high byte,
            //0x22 = CH2 low byte, 0x23 = CH2 high byte.
            8'h20: //Reading of the sample data for channel 1 ADC 1 from memory
              o_mcu_data <= o_adc1A_d;
        
            8'h21: //Reading of the sample data for channel 1 ADC 2 from memory
              o_mcu_data <= o_adc1B_d;
          
            8'h22: //Reading of the sample data for channel 2 ADC 1 from memory
              o_mcu_data <= o_adc2A_d;
          
            8'h23: //Reading of the sample data for channel 2 ADC 2 from memory
              o_mcu_data <= o_adc2B_d;
           
            //0x24..0x27 (0x153A): the pin as the IOB register took it on the last rising clk_200MHz edge (a liveness
            //read; it is not one of the capture stages)
            8'h24: //Reading of the sample data for channel 1 ADC 1
              o_mcu_data <= adc_q1[7:0];
            
            8'h25: //Reading of the sample data for channel 1 ADC 2
              o_mcu_data <= adc_q1[15:8];
            
            8'h26: //Reading of the sample data for channel 2 ADC 1
              o_mcu_data <= adc_q1[23:16];
            
            8'h27: //Reading of the sample data for channel 2 ADC 2
              o_mcu_data <= adc_q1[31:24];

            8'h28: //Reading of the external trigger status (0x1533 and later)
                    o_mcu_data <= { 5'b0, ext_activity, gen_out_enable, ext_level };
                    //bit0 ext_level:      EXT pin level after the synchroniser and the majority filter
                    //bit1 gen_out_enable: 1 = the generator drives the pin (cmd 0x50), EXT then reads it back
                    //bit2 ext_activity:   an EXT edge (either direction) since the last sampling reset (cmd 0x01 = 1)

            8'h29: //Reading of the decimation geometry (0x1534 and later), 2 bytes
                  4'h0:
                    o_mcu_data <= { dec_on, fir_en, fir_act, dec_neg_b, dec_neg_a, dec_swap, dec_order };
                    //bit7 = 1: 16-bit samples, one per channel per memory word (K >= 1)
                    //bit6 = 0x56 bit 0 (FIR enable as written), bit5 = FIR active now: enable, K >= 1 and
                    //divider >= 14 with divider bit 1 set (N >= 16, N a multiple of 4); both 0 before 0x1535
                    //bit4/bit3 = B/A cores captured on the falling write clock edge, bit2 = core order swap,
                    //bits 1..0 = K (0x53)
                  4'h1:
                    o_mcu_data <= { 2'b0, dec_shift };   //output shift (0x54)

            8'h2A: //Sequencer status (0x1536), 8 bytes
                  4'h0:
                    o_mcu_data <= { q_done, q_ovf, q_running, q_fmt16, seq_raw, q_circ, q_mode };
                    //bit7 run done (0x0A), bit6 circular segments wrapped at least once, bit5 running,
                    //bit4 records are 16-bit (0x53 K >= 1 at the arm), bit3 raw readout (0x57 bit 3, live),
                    //bit2 circular, bits 1..0 mode of the run armed last (0 = none: 0x57 was 0 or 3)
                  4'h1..4'h3:
                    o_mcu_data <= q_cnt[23:16], q_cnt[15:8], q_cnt[7:0];
                    //segments completed, or records accumulated (all positions)
                  4'h4..4'h5:
                    o_mcu_data <= q_untrig[15:8], q_untrig[7:0];
                    //untriggered records (auto time-out): segments stored with triggered = 0, or averaging
                    //records skipped; saturates at 65535
                  4'h6..4'h7:
                    o_mcu_data <= { q_st[2:0], 1'b0, q_idx[11:8] }, q_idx[7:0];
                    //sequencer state (0 idle, 1 restart, 2 record, 3 post-pass, 4 table, 5 next, 6 hold-off,
                    //7 done) and the slot / position the next record goes to.
                    //The count can change between its bytes while running: read twice and compare.

            8'h2B..8'h32: //Accumulator / segment table word at the read pointer (0x1536), bytes 0..7
                    o_mcu_data <= seq_lat[8 * (cmd - 0x2B) +: 8];
                    //Same pointer and pipeline as 0x20..0x23: set it with 0x1F (bits 10..0 used), one dummy read,
                    //then each read advances the pointer by one word. View word:
                    //  segment mode, or 0x57 bit 3 raw: the stored 64-bit word
                    //    segment table entry s: [39:0] timestamp (5 ns units from the first write clock edge
                    //    after 0x01 = 0), [52:40] trigger offset in the slot (trigger_address mod 2^m),
                    //    [53] triggered, [63] valid
                    //    raw averaging, legacy: four 16-bit sums CH1A, CH1B, CH2A, CH2B; 16-bit: CH1 sum [31:0],
                    //    CH2 sum [63:32]
                    //  averaging, legacy: lanes [15:0] CH1A, [31:16] CH1B, [47:32] CH2A, [63:48] CH2B = sum >> S
                    //  averaging, 16-bit: [15:0] min(65535, CH1 sum >> S), [47:32] min(65535, CH2 sum >> S), rest 0

            8'h33: //Encode self-check (0x1538): { last pin check CH2A, CH2B, CH1A, CH1B, 2'b01, prediction ok, sticky error }
                    o_mcu_data <= { enc_ok, 2'b01, enc_pred_ok, enc_err };   //0xF6 when all is right

            8'h36: //ADC capture (0x153A), 10 bytes high byte first
                  4'h0, 4'h1:
                    o_mcu_data <= cap_sel[15:8], cap_sel[7:0];   //the 0x63 value in effect (power-on 0x08E4)
                  4'h2, 4'h3:
                    o_mcu_data <= oc_1A[15:8], oc_1A[7:0];       //CH1 A outlier count since the last 0x01 = 1
                  4'h4, 4'h5:
                    o_mcu_data <= oc_1B[15:8], oc_1B[7:0];       //CH1 B
                  4'h6, 4'h7:
                    o_mcu_data <= oc_2A[15:8], oc_2A[7:0];       //CH2 A
                  4'h8, 4'h9:
                    o_mcu_data <= oc_2B[15:8], oc_2B[7:0];       //CH2 B
                    //A counter is the number of memory words (from the third one after the release of 0x01) whose
                    //sample of that core differs from the core's previous word by more than the 0x64 threshold,
                    //counted while the capture writes (saturating at 65535). With a quiet input (noise under the
                    //threshold) a well-captured core reads 0; a core captured inside its data transition reads
                    //about every word. Read after the capture (0x0A = 1).

            8'h34: //Trigger qualifier status (0x153C), 3 bytes
                  4'h0:
                    o_mcu_data <= { 2'b00, counting, pulse_began, trig_src_ext, trig_pw_long, trig_type[1:0] };
                    //bit5 Nth edge: counting (an idle gap was seen, or 0x60 = 0); bit4 pulse width: a sample off the
                    //pulse side was seen since the capture reset; bit3 the source is EXT (0x15 bit 1 as written);
                    //bit2 longer (0x5E bit 3); bits 1..0 = 0x5E bits 1..0 as written (bit 2 of the type is in 0x37)
                  4'h1..4'h2:
                    o_mcu_data <= rem[15:8], rem[7:0];   //Nth edge: edges still to count before the qualifying one,
                    //of the EXT qualifier when the source is EXT, else of the CH1 / CH2 one; asynchronous (read twice)

            8'h37: //Trigger extension status (0x153C), 1 byte
                    o_mcu_data <= { 3'b000, holdoff_running, trig_type[2], both_cores, trigger_core, 1'b0 };
                    //bit4 the trigger hold-off (0x1B) is running (no trigger is accepted); bit3 = 0x5E bit 2;
                    //bits 2, 1 reserved for 0x153E (both cores on, trigger core), read 0 here

            8'h35: //Counter (0x153C), 16 bytes from a snapshot taken when the command byte 0x35 is written (copied on the
                   //200 MHz side 15 .. 20 ns after the command strobe, so a gate ending during the read cannot tear it)
                  4'h0:  o_mcu_data <= { new, 1'b0, ext, ch2, 2'b00, gate };   //new: a gate ended since the last 0x35
                  4'h1:  o_mcu_data <= seq;                                     //sequence number of the result (8 bits)
                  4'h2..4'h5: E[31:0]  //periods between the first and the last rising edge in the gate (0: fewer than two
                                       //edges); 28 bits used
                  4'h6..4'h9: T[31:0]  //5 ns clocks between those edges
                  4'hA..4'hD: W[31:0]  //5 ns clocks high between them
                  4'hE:  o_mcu_data <= min;   //minimum raw code of the source's pair over the gate (both cores)
                  4'hF:  o_mcu_data <= max;   //maximum; 255 / 0 when no sample (EXT source, or before the first gate)
                  //frequency = E / (T x 5 ns), period = T x 5 ns / E, +width = W x 5 ns / E, duty = W / T. One read per
                  //screen pass: the command byte plus 16 data strobes.
//---------------------------------------------------------------------------------------
            8'h39: //Pattern status (0x153D), 4 bytes; asynchronous (the generator runs on the 200 MHz clock)
                  4'h0:  o_mcu_data <= { running, in_gap, pending, 2'b00, step[2:0] };
                    //bit7 a burst or gap is in progress; bit6 in the gap between bursts; bit5 a commit (0x6D bit 5) not yet
                    //taken; bits 2..0 the step in progress (0 when idle)
                  4'h1..4'h2: bursts[15:0]           //bursts completed since the last start, high byte first (wraps)
                  4'h3:  o_mcu_data <= { 6'd0, marker_seen, mode_active };
                    //bit1 a marked step started since the last 0x01 = 1; bit0 0x6D mode != 0

            8'h42: //Pattern trigger engine status (0x153D), 3 bytes laid out as 0x34
                  4'h0:  o_mcu_data <= { 1'b1, event_seen, counting, pulse_began, pt_src[1], pt_long, pt_type[1:0] };
                    //bit7 = 1: own engine (a second qualifier; 0 would be the contract's routed fallback); bit6 an event
                    //since the last 0x7D bit 2; bits 5..0 as 0x34 for the engine's registers 0x76 / 0x7A
                  4'h1..4'h2: rem[15:8], rem[7:0]  //Nth edge: edges still to count before the qualifying one

            8'h41: //Reading of the touch panel address needs loading of high byte first
                  4'h0:
                    o_mcu_data <= touch_panel_address[15:8];
                  4'h1:
                    o_mcu_data <= touch_panel_address[7:0];

//***************************************************************************************
//********************************* WRITING commands ************************************
//***************************************************************************************

                    sample_system_reset <= io_mcu_data[0];
                    
            8'h0B: //Loading 2 bytes of pretrigger_samples (set_trigger_point)
                  4'h0:
                    pretrigger_samples[12:8] <= io_mcu_data[5:0];
                  4'h1:
                    pretrigger_samples[7:0] <= io_mcu_data;
            
            8'h0C: //Loading two bytes of the total number of sample high byte first
                  4'h0:
                    total_samples[12:8] <= io_mcu_data[5:0];
                  4'h1:
                    total_samples[7:0] <= io_mcu_data;
        
            8'h0D: //Loading of the four bytes of the sample rate divider high byte first
                  4'h0:
                    sample_rate_divider[31:24] <= io_mcu_data;
                  4'h1:
                    sample_rate_divider[23:16] <= io_mcu_data;
                  4'h2:
                    sample_rate_divider[15:8] <= io_mcu_data;
                  4'h3:
                    sample_rate_divider[7:0] <= io_mcu_data;

                  4'h1:
                    time_base_set[23:16] <= io_mcu_data;
                  4'h2:

                  4'h3:

                    trigger_ext     <= io_mcu_data[1] & (0x5E type is edge);   //0x153C: the EXT edge path for the edge

                                                                               //EXT qualifier instead
                    //EXT: calibration pin P133, 3.3 V logic, generator must be off (cmd 0x50 = 0).
                    //Edge from cmd 0x16, mode/pretrigger/total/time-out unchanged, level (0x17) unused.
                    //trigger_address (cmd 0x14) = last sample written before the EXT edge, as for CH1/CH2.
                    //PATTERN (0x153D): the capture triggers on the first clock of a pattern step flagged mark, when
                    //0x6D bit 3 is set too (either alone never triggers: an auto capture times out); CH1 / CH2 / EXT
                    //and the qualified types are off; the position convention is EXT's (the marker is applied on the
                    //next write clock rise, 0x14 = the last word written before it). 0x16 / 0x5E are irrelevant.

            8'h16: //Setting the trigger edge (0x153C: the polarity per type, see 0x5E; edge type unchanged)
                    trigger_edge <= io_mcu_data[0] ^ (0x5E type is pulse width);   //the detect direction: the
                                                                                    //trailing edge of the pulse
            
            8'h17: //Setting the trigger level
                    trigger_level <= io_mcu_data;
          
            8'h1A: //Setting the trigger mode
                    trigger_mode <= io_mcu_data[0];
                           
            8'h1B: //Trigger hold-off, 4 bytes high byte first, 5 ns units, 0 = off (0x153C; up to 0x153B Atlan4's
                   //"hold on divider", stored and never used)
                  4'h0..4'h3:
                    trig_holdoff[31:24], [23:16], [15:8], [7:0] <= io_mcu_data;
                    //From the trigger of a record (the rise of 0x18) no trigger is accepted until 0x1B clocks of
                    //200 MHz have elapsed (exact, 5 ns .. 21.47 s). The timer is not reset by the sequencer's restarts
                    //nor by 0x01 = 1 alone, so a train's records keep their spacing across segments and MCU re-arms;
                    //0x66 bit 0 = 1 makes the next 0x01 = 1 clear it (a session restart), 0x1B = 0 releases the mask
                    //at once. An auto capture (0x1A = 0) whose time-out falls inside the hold-off ends untriggered
                    //(0x18 = 0, 0x14 = W - total + pretrigger). Read 0x37 bit 4 = running.
            
            8'h32: //Loading of the two bytes of the channel 1 DC offset high byte first
                  4'h0:
                    ch1_offset[15:8] <= io_mcu_data;
                  4'h1:
                    ch1_offset[7:0] <= io_mcu_data;
            
            8'h33: //Controlling of the channel 1 input sensitivity relays
                    relay1_1 <=  io_mcu_data[0];
                    relay1_2 <= ~io_mcu_data[1];
                    relay1_3 <= ~io_mcu_data[2];
            
            8'h34: //Controlling of the channel 1 input for AC or DC
                    ac_dc_1 <= io_mcu_data[0];

            8'h35: //Loading of the two bytes of the channel 2 DC offset high byte first
                  4'h0:
                    ch2_offset[15:8] <= io_mcu_data;
                  4'h1:
                    ch2_offset[7:0] <= io_mcu_data;
            
            8'h36: //Controlling of the channel 2 input sensitivity relays
                    relay2_1 <=  io_mcu_data[0];
                    relay2_2 <= ~io_mcu_data[1];
                    relay2_3 <= ~io_mcu_data[2];
 
            8'h37: //Controlling of the channel 2 input for AC or DC
                    ac_dc_2 <= io_mcu_data[0];
         
            8'h38: //Loading two bytes of the display brightness control high byte first
                  4'h0:
                    display_brigthness[15:8] <= io_mcu_data;
                  4'h1:
                    display_brigthness[7:0] <= io_mcu_data;
//---------------------------------------------------------------------------------------           
            8'h3C: //Loading two bytes of the touch panel read address high byte first
                  4'h0:
                    touch_panel_address[15:8] <= io_mcu_data;
                  4'h1:
                    touch_panel_address[7:0] <= io_mcu_data;
                    
            8'h50: //Setting the output on or tristate (off = pin usable as EXT trigger input)
                   gen_out_enable <= io_mcu_data[0];
                    //0x153D: 1 = the pin carries the pattern generator's level (0x6C .. 0x6F below; with the pattern
                    //off, the idle level of 0x6D bit 2, power-on 0). Every data byte writes bit 0 (the firmware's
                    //4-byte write ends with the low byte).

            8'h51, 8'h52: //Retired in 0x153D (the DDS phase increment and duty of 0x1532 .. 0x153C): no decoder entry,
                          //the bytes are ignored. The square wave is the two-step pattern of 0x6C / 0x6D.

// Decimation filter (0x1534). Details: fpga/al3/README.md "Changes" section 3.
// N = 2 * (floor(divider / 2) + 1), divider from 0x0D; output rate 200 MSa/s / N (odd divider: as K = 0).
// With K >= 1 the ADCs always run at 200 MSa/s and the filter output (gain N^K) is stored as
// min(65535, y >> shift). Exact while 255 * N^K < 2^48 (K = 3: N <= 10334).
// 0x0B, 0x0C, 0x0E and 0x14 count memory words = output samples. Latency from the captured word (adc*_w) to the
// memory: 12 write clocks; the capture itself adds its stages (0x153A, README section 10).

            8'h53: //Decimation filter configuration, 1 byte
                    dec_order <= io_mcu_data[1:0];  //K: 0 = sample skipping (0x1533), 1 = boxcar, 2 = CIC2, 3 = CIC3
                    dec_swap  <= io_mcu_data[2];    //0 = core B is the earlier sample of a pair (firmware interleave)
                    dec_neg_a <= io_mcu_data[3];    //0x1534..0x1539: A cores captured on the falling write clock edge;
                    dec_neg_b <= io_mcu_data[4];    //0x153A: read back in 0x29, no effect (0x63 selects the capture)

            8'h54: //Decimation filter output shift, 1 byte
                    dec_shift <= io_mcu_data[5:0];  //recommended max(0, bitlen(255 * N^K) - 16)

            8'h55: //Loading two bytes of the 16-bit trigger level high byte first (used when K >= 1, 0x17 is ignored)
                  4'h0:
                    trigger_level16[15:8] <= io_mcu_data;
                  4'h1:
                    trigger_level16[7:0] <= io_mcu_data;

//---------------------------------------------------------------------------------------
// CIC compensation FIR (0x1535). Details: fpga/al3/README.md "Changes" section 5.
// Engages when 0x56 bit 0 = 1, K >= 1, N >= 16 and N a multiple of 4 (divider >= 14, divider bit 1 set);
// otherwise the 0x1534 path runs unchanged. The CIC then decimates by N/2 (gain (N/2)^K), its output is
// min(65535, y >> shift), and a 15-tap symmetric FIR (DC gain 1, one tap set per K) decimates by 2:
// stored = clamp(0 .. 65535, round(FIR)). Output rate, memory layout and read-back as 0x1534.
// Recommended shift: max(0, bitlen(255 * (N/2)^K) - 16) + 1 (+1: headroom for the 6-9 % step overshoot).
// Latency pin to memory: 25 write clocks; EXT data lag 250 + 17.5 N + 1.25 K (N - 2) ns.
// After changing 0x0D, 0x53, 0x54 or 0x56 wait (K + 10) * N * 5 ns + 1 us before 0x01.

            8'h56: //CIC compensation FIR, 1 byte
                    fir_en <= io_mcu_data[0];       //1 = FIR on where eligible; bits 7..1 reserved, write 0

//---------------------------------------------------------------------------------------
// Segmented capture and hardware averaging (0x1536). Details: fpga/al3/README.md "Changes" section 6 and
// docs/plans/segmented-capture.md. Write 0x57..0x5C while 0x01 = 1 (they are latched there); 0x0B, 0x0C,
// 0x0E, 0x15..0x1A and 0x53..0x56 apply to every record of the run. A run ends with 0x0A = 1.
// Segments: 0x58 slots of 2^m words (0x59), slot s at words s * 2^m; per segment a normal capture with
// pretrigger 0x0B and total 0x0C (total <= 2^m - 2), then a table entry (read 0x2B..0x32 word s), the
// hold-off 0x5C and an automatic restart. Averaging: each triggered record (pretrigger included) is added
// into accumulator words p * total .. p * total + total - 1, p = record index mod 0x58 positions,
// 0x5A records per position; positions * total <= 2048, total <= 2046. Untriggered records are skipped.

            8'h57: //Sequencer mode, 1 byte
                    seq_mode <= io_mcu_data[1:0];   //0 off (power-on), 1 segments, 2 averaging, 3 off (reserved)
                    seq_circ <= io_mcu_data[2];     //segments: circular, wrap at 0x58 and run until 0x5D
                    seq_raw  <= io_mcu_data[3];     //averaging readout: raw sums (live, also after the run)
                                                    //bits 7..4 write 0

            8'h58: //Segments or averaging positions, 2 bytes high byte first
                  4'h0:
                    seq_count[11:8] <= io_mcu_data[3:0];
                  4'h1:
                    seq_count[7:0] <= io_mcu_data;  //segments 1 .. 8192 >> m, positions 1 .. 2048 / total

            8'h59: //Segment slot size, 1 byte
                    seg_m <= io_mcu_data[3:0];      //slot = 2^m words, m = 5 .. 12

            8'h5A: //Records per averaging position, 2 bytes high byte first
                  4'h0:
                    avg_n[15:8] <= io_mcu_data;
                  4'h1:
                    avg_n[7:0] <= io_mcu_data;      //1 .. 65535, 0 = 65536; legacy lanes clamp at 65535 above N = 257

            8'h5B: //Averaging readout shift, 1 byte
                    avg_shift <= io_mcu_data[4:0];  //S, live: the record can be read again with another S

            8'h5C: //Hold-off, 4 bytes high byte first, 5 ns units
                  4'h0..4'h3:
                    seq_hold[31:24], [23:16], [15:8], [7:0] <= io_mcu_data;
                    //wait from the end of a segment's table write / a record's post-pass to the restart

            8'h5D: //Stop, 1 byte
                    seq_stop <= io_mcu_data[0];     //1 = no further restarts: an untriggered record in progress is
                                                    //abandoned (its slot entry stays invalid), a triggered one
                                                    //completes; then 0x0A = 1. Cleared by 0x01 = 1.

//---------------------------------------------------------------------------------------
// ADC capture (0x153A). Every ADC pin is sampled by an IOB DDR register on clk_200MHz; a write clock edge E sees
// the pins as they were 5 + 2.5 k ns before it (stage k = 0..5). Core A of a chip is encoded on the falling write
// clock edge and captured against it, core B on the rising edge and captured against that, so each core's data
// window has the same position relative to its own edge at every sample rate; stages 3 and 4 lie inside it with
// 1.3..2 ns to spare against the AD9288 limits (tV 2 ns, tPD 6 ns) on the owner's unit per TD's numbers, 2 and 5
// are reserves for a drifted window. A word holds the B sample encoded T/2 before its A sample (B first) at every
// rate. Setting a core inside its transition gives rail values and jumps, not a shifted trace: train with 0x36.

            8'h63: //ADC capture stages and B reference, 2 bytes high byte first; power-on 0x08E4
                  4'h0:
                    cap_sel[15:8] <= io_mcu_data;   //bit 13 CH2 B / bit 12 CH1 B timed by the chip's A encode (ADC
                                                    //data-align mode; power-on 0 = by its own encode), [11:9] CH2 B stage
                  4'h1:
                    cap_sel[7:0] <= io_mcu_data;    //[8:6] CH2 A stage, [5:3] CH1 B, [2:0] CH1 A (6 and 7 act as 5)
                    //Takes effect at the next write clock edges; write it before 0x01 = 1 of the capture it is for.

            8'h64: //Outlier threshold for the 0x36 counters, 1 byte, codes; power-on 8
                    cap_thr <= io_mcu_data;

//---------------------------------------------------------------------------------------
// Trigger types (0x153C C1). Details: fpga/al3/README.md "Changes" section 12, docs/plans/fpga-0x153c.md section 3.
// Units of N and H: CH1 / CH2 = samples of the trigger stream (one per memory word: legacy core A of the channel,
// K >= 1 the 16-bit output samples); EXT = 5 ns clocks. The level is the edge trigger's (0x17, or 0x55 with K >= 1).
// The trigger position is the edge trigger's for the qualifying edge (0x14 = the word of the trigger sample - 1;
// timeout: the qualifying sample); EXT qualified types decide 5 ns after an EXT edge trigger on the same edge.
// 0x5E, 0x5F, 0x60 are latched like 0x15..0x17: written any time before 0x01 = 0 (also inside the 0x01 = 1 window
// after the 0x05 wait, at every rate). The qualifier restarts with each record (sequencer restarts included).
// Power-on 0x5E = 0 (edge): identical to 0x153B.

            8'h5E: //Trigger type, 1 byte
                    trig_type    <= io_mcu_data[2:0];  //0 edge, 1 pulse width, 2 Nth edge, 3 timeout; 4 runt and
                                                       //5 window are 0x153E (here, like 6 and 7, they act as edge)
                    trig_pw_long <= io_mcu_data[3];    //pulse width: 1 = longer than N, 0 = shorter than N
                                                       //bits 7..4 reserved (0x153E: bit 4 range, bit 5 both cores), write 0
                    //0x16 per type: edge = the edge; pulse width 0 = positive pulse (trigger on its falling edge),
                    //1 = negative pulse; Nth edge = the counted edge; timeout 0 = held high after a rising edge,
                    //1 = held low after a falling edge.
                    //Pulse width: fires on the trailing edge of a pulse of w samples with w < N (shorter) or w > N
                    //(longer); the pulse must have begun after the capture reset (a sample off the pulse side seen).
                    //Nth edge: the Nth edge in the counted direction, counted from the arm (the pretrigger filled,
                    //0x60 = 0) or from the start of each burst (the count restarts when the level has held for H
                    //samples without any edge, 0x60 = H).
                    //Timeout: the sample that makes the held run N + 1 samples long after the edge (or the arm), no
                    //edge needed.

            8'h5F: //N, 3 bytes high byte first: pulse width / timeout 1 .. 2^24 - 1 samples (N = 1 degenerates to the
                   //edge type with one sample of context); Nth edge bits 15..0 (1 .. 65535, 0 acts as 1)

            8'h60: //Nth edge idle time H, 3 bytes high byte first, samples: the count restarts when the level has held
                   //for H samples (a burst); 0 = edges count from the arm (pretrigger filled)

            8'h66: //Hold-off clear request, 1 byte
                    ho_clr_req <= io_mcu_data[0];      //1: the next 0x01 = 1 also clears the hold-off timer of 0x1B
                                                       //(one-shot, consumed by that 0x01 = 1)

//---------------------------------------------------------------------------------------
// Pulse pattern generator (0x153D, D2). Details: fpga/al3/README.md "Changes" section 15, docs/plans/fpga-0x153c.md
// section 7. The generator since the DDS went: 0x50 = 1 drives the calibration pin with the pattern's level. A table of
// 8 steps (0x6C), each a level, a marker flag, an end flag and a duration of n + f / 65536 clocks of 5 ns (n >= 2; the
// edges land within one clock of their ideal time, the mean duration is exact: one Bresenham accumulator, cleared at
// every burst start only). A burst = steps 0 .. the first end (entry 7 acts as end). Modes (0x6D): 1 one burst per
// start, 2 R bursts (0x6E) with a gap (0x6F) between them, 3 continuous (gap after every burst; gap 0 = seamless), 0 off.
// A start = 0x6D bit 4, the pattern trigger engine's event (0x76 .. 0x7D) or the write of mode 3 while idle; a start
// while a burst or gap runs is ignored. Entries 0 and 1 are double-buffered: their writes land in shadows, 0x6D bit 5
// marks them pending, the first step boundary after that (a start counts) takes them; the step starting at that boundary
// was already queued, so the new values apply from the step after it (at a start: from step 0), glitch-free and with the
// accumulator kept. The square wave of the generator menu: entry 0 = high (n_h, f_h), entry 1 = low with end (n_l, f_l),
// mode 3: f = 200 MHz x 65536 / P16, P16 = the period in 1/65536 clocks (section 7.4's P16 / H16 arithmetic). Power-on:
// everything 0 (mode off, the pin hi-Z until 0x50 = 1, then the idle level 0).

            8'h6C: //Pattern step, 7 bytes
                  4'h0:
                    { end, mark, level, index[4:0] } <= io_mcu_data;   //index 0 .. 7 (8 .. 31: the write is ignored)
                  4'h1..4'h4:
                    n[31:0] <= io_mcu_data;         //integer duration, 5 ns clocks, high byte first; >= 2
                  4'h5..4'h6:
                    f[15:0] <= io_mcu_data;         //fraction, 1/65536 clock, high byte first; the entry is handed to the
                                                    //generator on this byte (index 0 / 1: into the shadow)

            8'h6D: //Pattern control, 1 byte
                    mode      <= io_mcu_data[1:0];  //0 off (the pin at the idle level; a running burst is abandoned at
                                                    //once), 1 single burst, 2 R bursts, 3 continuous (starts by itself
                                                    //when written while idle)
                    idle      <= io_mcu_data[2];    //the level between bursts and in mode 0
                    mark_trig <= io_mcu_data[3];    //the marker is the capture's trigger source (with 0x15 = 3)
                    start     <= io_mcu_data[4];    //start now (self-clearing; ignored while a burst or gap runs and in
                                                    //mode 0, and when bits 7..6 = 1 or 3)
                    commit    <= io_mcu_data[5];    //the shadow entries 0 / 1 become pending (self-clearing; a second
                                                    //commit before they are taken replaces them)
                    source    <= io_mcu_data[7:6];  //who starts a burst: 0 the MCU (bit 4), 1 the pattern trigger
                                                    //engine, 2 both, 3 the engine
                    //A 0x6D write takes effect 3 .. 4 clocks (15 .. 20 ns) after the data strobe's rising edge; step 0 of a
                    //burst it starts begins 5 clocks after that (about 40 .. 45 ns after the strobe). A commit is taken at
                    //the next step boundary (or the start): the two steps already queued keep the old entries, the new
                    //ones apply from the third boundary after the commit (at a start: from step 0).

            8'h6E: //Bursts per start in mode 2, 2 bytes high byte first (0 = 65536)

            8'h6F: //Gap between bursts, 4 bytes high byte first, 5 ns clocks (0 = none); at the idle level

//---------------------------------------------------------------------------------------
// Pattern trigger engine (0x153D, D2). A third trigger qualifier (module trig_qual, as the capture's two) on the same
// streams the capture's qualifiers watch, with its own level: CH1 / CH2 = the trigger stream sample of every memory word
// (legacy core A of the channel, K >= 1 the 16-bit output word), EXT = the filtered pin level at 5 ns. Units of N and H
// as the capture's (words for CH1 / CH2, 5 ns for EXT). Its event starts a burst when 0x6D bits 7..6 allow it and sets
// 0x42 bit 6 either way. Latency: the burst's step 0 begins 6 clocks (30 ns) after the event clock, which is 7.5 ns
// after the write clock edge of the qualifying sample (CH1 / CH2: 37.5 ns after that word's write edge; the ADC pipeline
// before it is the capture's) or about 5 clocks after the pad edge (EXT: pad edge to burst 51 .. 60 ns in simulation).
// The engine never touches the capture's timed path; the capture may use any trigger at the same time (own engine,
// 0x42 bit 7 = 1).
// Power-on: everything 0 (disarmed).

            8'h76: //Source, 1 byte: bits 1..0 = 0 CH1, 1 CH2, 2 / 3 EXT (as 0x15; 3 is EXT here, not the marker)
            8'h77: //Polarity per type, 1 byte: bit 0 (as 0x16)
            8'h78: //Level, 1 byte, raw ADC code (as 0x17; the legacy stream)
            8'h79: //Level, 2 bytes high byte first, 16-bit (as 0x55; K >= 1)
            8'h7A: //Type, 1 byte: bits 2..0 = 0 edge, 1 pulse width, 2 Nth edge, 3 timeout (4 .. 7 act as edge); bit 3
                   //pulse width longer than N (as 0x5E)
            8'h7B: //N, 3 bytes high byte first (as 0x5F)
            8'h7C: //Idle time H, 3 bytes high byte first (as 0x60)
            8'h7D: //Engine control, 1 byte
                    armed  <= io_mcu_data[0];       //1 = the engine watches (writing 1 restarts its state, as 0x01 does
                                                    //for the capture's qualifier); one shot: the event clears it
                    rearm  <= io_mcu_data[1];       //1 = re-arm after each burst: the qualifier is held in reset while
                                                    //the burst runs and restarts when it ends
                    clear  <= io_mcu_data[2];       //1 = clear the event flag (0x42 bit 6), self-clearing
                    //Firmware order: 0x7D = 0, then 0x76 .. 0x7C, then 0x7D = armed | rearm << 1 | 4.

//---------------------------------------------------------------------------------------
// Hardware counter with min / max (0x153C, C3). Details: fpga/al3/README.md "Changes" section 13, the contract
// docs/plans/fpga-0x153c.md section 5. Power-on: 0x61 = 0 (off), 0x62 = 0 / 0 (the firmware writes 128 / 6 at boot).
// Source stream: EXT = the filtered pin level (one bit per 5 ns); CH1 / CH2 = the captured pair of every write clock
// (core B then core A, T/2 apart) through a Schmitt trigger: high at code >= level, low at code < level - hysteresis
// (hysteresis >= level: never low). 5 ns resolution at 200 MSa/s (divider 0 or any K >= 1), each sample held half a word
// at slower legacy rates. The gate is exactly 2e6 / 2e7 / 2e8 clocks of the 200 MHz clock; from the first rising edge
// in the gate to the last: E periods, T clocks, W high clocks, plus the pair's min and max over the whole gate (both
// cores). Published with a sequence number at the end of every gate; a 0x61 write restarts the gate (the first result
// one gate after it). Range: about 1 Hz (two edges in a 1 s gate) to 100 MHz; T and W are 28 bits.

            8'h61: //Counter control, 1 byte
                    cnt_gate <= io_mcu_data[1:0];      //0 off, 1 = 10 ms, 2 = 100 ms, 3 = 1 s (2e6 / 2e7 / 2e8 clocks)
                    cnt_src  <= io_mcu_data[3:2];      //0 the trigger source (0x15 as written: 2 / 3 = EXT, 1 = CH2,
                                                       //0 = CH1), 1 CH1, 2 CH2, 3 EXT

            8'h62: //Counter level and hysteresis, 2 bytes
                  4'h0: cnt_lvl <= io_mcu_data;        //raw ADC code: high at >= level
                  4'h1: cnt_hys <= io_mcu_data;        //low below level - hysteresis
