## 2. Hardware
### SoC / boot
- SoC Allwinner F1C100S, no internal flash. BROM tries SD card boot header first, then SPI flash at address 0 [p102, pcprogrammer #2536]. Stock flash is W25Q16 (or W25Q32) [p102].
- Original code in flash starts at 0x27000 and uses the same BROM header with a length to load [p91 #2255]. Original bootloader at flash 0x00000 [p102 #2549]. Stock settings: 500 bytes at flash 0x001FD000 [p103 #2574].
- Flash backup is 2048 kB (2 MB); original firmware image ("FWB") ~1964 kB; main firmware ~1840 kB [p91, p105, p106].
- Boot time limited by FPGA configuration time, not SD speed; firmware loads to DRAM at boot; SD clock tops out just under 50 MHz [p110 #2748].
- FEL (Allwinner USB boot): works when neither SD nor flash has a boot program. Stock FEL does not enable DRAM; starting FEL from the bootloader does, so code can be loaded into DRAM. No PC-triggered reset (power cycle needed). Raw binary from .elf is uploaded with sunxi-fel (Linux only); binary loaded 32 bytes before memory start (BROM header size) so vectors line up [p91, pcprogrammer #2274]. Used for developing both 1013D and 1014D firmware.
- USB: pcprogrammer's `f1c100s_ch340` test code emulates a CH340 toward the host to test USB device mode and FPGA communication; it is not a serial port to the F1C100s UART, link is baud-independent, control handling not implemented. Using F1C100s UART requires extending the code [p104, #2598-#2599]. Atlan later said a USB virtual COM port was "programmed" [p107 #2663] and "CH340 mode would create a PC serial port; current USB program doesn't work with it yet" [p117 #2904].
- Power-off: MCU gets an interrupt, runs power-down sequence, delays the 3.3 V regulator's POWER_ENABLE so settings can be written to SD. Too short a delay (e.g. spare 5 V boost supply wired after battery switch) loses settings [p101 #2524, p102 #2525]. Spare supply via POWER_ENABLE draws ~20 uA in sleep [p102 #2526].
- Battery voltage read via F1C100S key ADC, only 6-bit; icon jitter; stock firmware compensates reading using a formula because FPGA current varies with sample settings [p99 #2462, #2465]. Step-up converter: 4.2 V LiPo in, +5 V out [p91 #2253]. Original battery measured ~4.5 Ah by Dbuezas, replaced by 16 Ah [p114 #2825]; Fnirsi website quotes 6000 mAh, ~4 h [p112 #2788] (contradiction, see section 10).
- Backlight: PWM carrier ~800 Hz at reduced brightness causes audible coil whine; always-100% avoids it [p101 #2504, #2508]. Atlan added max-light toggle and saved brightness (v0.025u/x) [p101, p104].
- Atlan: separate supplies per part (MCU, FPGA, ADC, ...) reduced noise to 0-1 counts; original design apparently did not extend supply to input amplifier [p104 #2590]. Noise ~2 bits, mainly CH2 [p98 #2445]. Destroyer93: ~20-30 mV RMS idle noise, seen at ~35-40% battery, blocked DC-shift calibration [p107 #2653, #2656].

### Display / touch
- Display timing words in firmware/bootloader (little-endian pairs, found in 0x04xxxx region, e.g. 0x04F350 / 0x04E918 in two files): 1014D new 0x041E0043/0x041A0019; 1014D old 0x041E006D/0x041A0022; 1013D v1 0x041E0044/0x041A0017; v2 0x041E004A/0x041A0017; v3 0x041E0072/0x041A001F [p103 #2558, pcprogrammer]. Search by byte pattern (e.g. 44 00 1E 04 17 00 1A 04).
- Config sector (28+ bytes): AA AA AA AA 55 55 55 55 | TCON0_BASIC_TIMING1 (0x041E004A) | TIMING2 (0x041A0017) | CC CC CC CC 33 33 33 33 | checksum (sum of first six 32-bit words, standard value 0x0838005F) | swap bytes (FF FF = no swap, 00 = swap X,Y) [p106 #2634/#2639 Atlan; p95 #2372, pcprogrammer: checksum covers first six words only, swap bytes after checksum, loader reads a whole sector]. Config stored at SD sector 710 (also referenced: calibration data in sector 708) [p92 #2309, p96 #2390].
- Boot-mode byte: sector 710, byte 32 (Atlan, 1-indexed?) / "byte 31" (Sleo; likely 0-indexed, inference). Values: 0x00 PECO no menu, 0x01 FNIRSI no menu, 0x02 FEL no menu, 0x04 PECO with menu, 0x05 FNIRSI with menu, 0x06 FEL with menu; default 0xFF [p96 #2396/#2399; p95 #2372; p97 #2400/#2406]. Recovery from bad FEL setting: zero the byte (HxD) or reformat card; pcprogrammer: write 0xFF to sectors 16-800 [p97, p109 #2700].
- Touch controller GT911 (original); replacements seen GT9157 (interchangeable but config differs), 1024x600 config vs 800x480 original [p105 #2601, #2616]. Original firmware rewrites TP config at startup. Fix: patched main.bin where bytes at 0x03EAA8 become 00 00 A0 E1 (ARM NOP replacing call to TP-configure routine) [p106 #2627, #2645]. Restore program `fnirsi_1013d_fwr.bin`: reads FNIRSI_1013D_main.bin (-> flash 0x27000) or FNIRSI_1013D_full.bin (-> flash 0x0) from SD root, no validity check, self-deletes [p106 #2627]. TP-config writer `fnirsi_1013d_tpc.bin` reads FNIRSI_1013D_tp_config.bin (>=186 bytes), writes to panel, needs power cycle; default 14 sensors/24 drivers though pcprogrammer has only seen 12/19 panels [p106 #2638].
- GT911 registers: resolution 0x8048-0x804B must not change; sensor count 0x8064; sensor-line map 0x80B7-0x80C4; driver map 0x80D5-0x80EE; unused entries 0xFF; reversing order of the arrays flips direction; reversal bits on p5 of programming guide [p106 #2641]. Touch vertical flip: last byte of configuration_file.txt = 0x00 [p104 #2596]; Atlan recommends Loader 1.1.3 for it [p104 #2597]. One 28x16-line panel vs 26x14 supported sensors [p105 #2621]; 18x12 -> 18x13 replacement worked after flashing TP config first, but pcprogrammer says startup rewrites config and extra sensor lines limit range without modified firmware [p107 #2664-#2665].
- Display replacement shifts image; original firmware via boot menu jumps to 0x27000 so display init differs; pcprogrammer suggests booting original bootloader from flash 0x0 [p102 #2541, #2549; p103 #2551].
- Stock cursor positions in flash: time cursor 1 at 0x001FD144 (16-bit LE, cursor 2 follows), volt cursor 1 at 0x001FD14A; bad saved values can park cursors off-screen [p103 #2574].
- Bit-banged I2C (TP, RTC): max port speed measured 2.5 MHz with SCL toggling, TP bus basic setting 172 kHz [p96 #2390]. A capacitor between SCL and SDA exists (pcprogrammer: workaround for bit-bang I2C); Sleo desoldered it: 20 pF NP0 0603 ~50 V; in-circuit readings of 2.2 nF are invalid; scope works without it (sub77) [p96 #2376-#2377; p106 #2631-#2632].
- An 8-pin SOP "special IC" is not used by open-source firmware, purpose unknown [p109 #2717, pcprogrammer].

### RTC / SD / USB / misc
- DS3231 RTC modules solder-in (3.3 V and GND on pads; layout differs on some boards, Dbuezas found unpopulated pads) [p95 #2360, p114 #2825]. Firmware v0.025p+ has RTC; timestamps on Save Pic/Save Wave (file attributes, later burned into picture in v0.26r2) [p99, p120]. Wrong time after DST seen [p110 #2746]. Stock firmware has no RTC; patching it in infeasible [p96 #2394].
- SD cards: some old cards (4 GB class 6, 1 GB) fail on new firmware but work on stock; suspected speed/high-speed mode negotiation (pcprogrammer, same on 1014D; Milk-V Duo took 2.5 min with that card) [p96 #2378-#2379]. Corrupt calibration data on the card also caused "SD" failure; new cards or cleared calibration fixed [p95 #2363]. Single FAT partition, free space before it (1 MB enough); hidden sectors >= 1023 (8191/16383 suggested); GPT unsupported; firmware lives at SD sector 16 and is not erased by formatting; partition offset 4194304 bytes quoted in manual [p93-95, p102 #2540/#2547, p111 #2756, p119 #2964]. 32 GB SanDisk FAT32 worked [p117 #2909]. Stock firmware SD update: checks filename, clears start sector at flash 0x27000, reboots, bootloader writes with progress; new FNIRSI file (1013D.bin 2024) differs substantially from older binaries; CRC issue freezes at 100% on restore [p108 #2677-#2682].
- CH341a warning: some CH341a boards switch Vcc to 3.3 V but leave SPI at 5 V and kill the flash (pcprogrammer killed one) [p103 #2567].
- Atlan: "five soldered flash chips for the FPGA", programming the wrong flash can brick [p109 #2718]. Atlan uploaded to flash twice and the scope died both times; unplugging the flash and re-uploading fixed it [p115 #2854].
- Hold on/Hold off: Hold button in trigger menu intended to set delay between two triggers [p111 #2773].
- Chip marking oddity: Destroyer93 read "2515" on a chip near ADC/FPGA; cte said "2415" looks like a date code [p107 #2653, #2657]. Unresolved.
- PCB signal path (1014D, from schematic): BNC -> divider/filter -> op-amp U17 (CH1) -> ADC -> FPGA sample memory; FPGA-generated offset voltage partly controls ADC reading; check smoothing caps C28/C29. 1014D BNC ground rings lifted to ~1.2 V, input swing ~0..2.5 V [p116 #2881, #2883, pcprogrammer].
- AC/DC coupling: series capacitor shorted by FET for DC; no hardware GND switch [p93 #2314].

## 3. FPGA
- Variants discussed: Altera Cyclone IV (older units, external flash, JTAG via bitblaster), Anlogic AL3-10 (external flash, JTAG), Anlogic EF2 family (internal flash; newer full-glass-panel boards; no 25Q80 flash on those PCBs; "ELF2"/EF2L45-class; L = FPGA+flash, M = +Cortex-M3, S = +PSRAM) [p94 #2333, p100 #2488-#2491, p110 #2737, #2740, p118 #2941].
- FPGA config comes from a separate flash chip or JTAG, no USB path [p94 #2333]. Original FPGA flash binaries in the Hack repo. Atlan's EF2 board has no flash; unknown if read-protected; reprogramming would drop original-firmware compatibility [p100 #2488, p115 #2854].
- Same FPGA design is used in old and new scopes; same F1C100/FPGA family reported in DPOX180H (50,000 wfms/s advertised) [p98 #2430, p110 #2737].
- Original RE'd FPGA design: pcprogrammer says he only partly reverse engineered it, found it poor (no timing constraints, async ADC reads) and his re-synthesis attempt did not work; needs timing constraints, synchronous design, minimal clock domains [p110 #2726, p115 #2855, p100 #2493]. Atlan: "PC's FPGA code does not work correctly, especially trigger" [p110 #2735].
- Command interface (MCU->FPGA): 0x0D = sampling frequency (ADC clock); 0x24/0x25/0x26/0x27 read ADC1_A, ADC1_B, ADC2_A, ADC2_B buses directly, clocked by last ADC clock, not synchronised, so averaging/filtering is in software [p98 #2439, pcprogrammer]. Atlan removed unused commands 0x28 and 0x3C in v0.025n [p98 #2433]. FPGA has `touch_panel_address[15:8]/[7:0]` registers written from `io_mcu_data` in mcu_state cases 4'h0/4'h1 and read back; pcprogrammer: always return what stock firmware expects, use another register or new command for new settings [p110 #2738-#2739]. Atlan notes ADC data pins AD0/AD1 matter for small signals; ADC clock connected via a gate (Cinan's design) [p98 #2445].
- Sample memory: FPGA captures 3000 samples/channel; design uses 1500 around trigger centre; screen shows ~750 [p99 #2452, p111 #2760]. Atlan claims RAMFIFO could give 2x65535, 2x8000 theoretical but timing problem; would break FNIRSI-software compatibility [p113 #2817, p119 #2974]. Long-memory mode failed against the FPGA limitation and was removed in v0.026a [p107 #2663, #2666]. pcprogrammer earlier: "4 KB per channel, not fully used" [p95 #2351].
- Sample rates: stock 1013D ~200 MSa/s (not 1 GSa/s); 100 MSa/s per ADC interleaved (inference from "50 MHz clock -> 100 MSa/s per channel, 60 MHz would be 120"), pcprogrammer: raising crystal to 60 MHz stretches ADCs [p100 #2493].
- Wishes: trigger on left edge needs FPGA change [p110 #2734]; external trigger on the pin labelled "1khz" (3.3 V logic, BNC drilled in, hold-off, selectable square-wave frequency/duty) [p115 #2854, p117 #2922]; 5 mV input amplifier + new FPGA program (breaks compatibility) [p113, p118 #2936]; signal generator on test pin via new FPGA; Atlan idea: desolder F1C100S flash and wire to FPGA flash (pcprogrammer: bus-conflict risk; better to set FPGA to serial slave mode and load bitstream from SD) [p117 #2924, p118 #2925]. Atlan needs help tracing ADC-to-FPGA pins on EF2 boards [p110 #2740]. Atlan: FPGA signals "don't arrive where they should", ADC on arbitrary FPGA pins [p115 #2854].

## 4. ADC and analog front end
- ADC is 8-bit [p107 #2669]; stock firmware shows change only >6 counts (about 8-bit resolution at 100 mV) [p109 #2724].
- Two ADCs interleaved per channel; "adc comp" corrects the sampling pattern; typical +2/-2, some units 4/-3. Compensation applied to ADC1 before ADC2; splitting widens usable range 0-249 to 0-252 for an offset difference of 6 [p100 #2487, p104 #2589].
- Per-range calibration points: one per input divider (100 mV/div to 5 V/div); more points would not help [p98 #2444-#2445].
- Bandwidth/limits: pcprogrammer ~30 MHz not 100; Atlan "30 MHz, 100 mV sensitivity, no trigger input"; Russell sees ~20 MHz limit [p95 #2351, p95 #2354, p113 #2812]. Stock firmware draws a computed sine above ~40 MHz using capture for frequency/amplitude only and amplitude error reversed [p94 #2332]. Alt firmware draws straight lines between points (no sin(x)/x; sinc suggested) [p94 #2336, p100 #2480]. Stock sensitivity below 100 mV with 50 mV/div doubling issue: in long timebase stock firmware does not multiply samples x2 at 50 mV/div; fix would be assembly patch using Ghidra project [p103 #2555].
- Marketing: "Upgraded 1013D Plus" model is 100X probe + two normal probes, no bandwidth change; both channels have independent sensitivity [p109 #2720-#2721, p110 #2732].
- 1013D DC accuracy spec ±2% at 5 V/div (tunk) [p91 #2263].

## 6. Calibration procedures
- Order (Atlan): charge; warm up >=5 min (3 min older); basic calibration (cables disconnected); input-divider calibration (needs stable ~300 mV / 600 mV / 1.5 V etc., prompts); DC-offset calibration (align trace to channel cursor, zero signal, zero Vmin); back up with Loader [p97 #2423, p98 #2426].
- DC shift parameters: 1 `dc_shift_center` (default 112, min 50-100), 2 `dc_shift_size`, 3 `dc_shift_value` / Vmin (default 385, limit raised 350->400->430); procedure: one channel, 5 Vpp sine/square with 2.5 V offset, autoset, then disconnect for params 2/3 [p92 #2299, p96-97]. Reset via diagnostic menu then base cal brings back 300 mV prompt [p104 #2594]. Diag values range -3..+4 for channel deviation [p118 #2936]. Base calibration default 860 [p95 #2350]. `scope_do_baseline_calibration()` sets PWM so converter output is mid-range ADC (127); "offset calibration failed" implies bad op-amp or BNC resistors [p106 #2649].
- Reference sources: LED+resistor+caps+50k trimmer, LM317 + 50k pot, Li-ion packs/9 V pairs + divider, avoid switchers/walls (ripple/noise) [p109, p119-p120].
- Original FNIRSI constants are likely not compatible; firmware works uncalibrated but measurements and trigger are wrong [p119 #2971].

## 7. Measurements and artifacts
- Stock firmware reconstructs waveform; new firmware plots raw samples, visible "kink" on rising edge at 1 kHz test signal; at high frequency shows stair/lines [p100 #2477-#2480].
- 22 MHz sine looks poor on alt firmware vs stock; Owon XDS2102A comparison (12-bit, 1 GSa/s) judged apples/oranges [p94].
- Vpp readout jitter 0.1-0.2 V on built-in 1 kHz [p113 #2810]. 500 Hz square mis-measured in DC coupling autoset (fixed v0.025y) [p99 #2458, p107 #2658]. Waveform drawn too small at x100/5 V/div, x20/1 V/div, x10/500 mV/div (digital value right) [p110 #2743].
- Freeze with long memory ON; fixed by removing long memory [p101 #2513, p107 #2661, #2663]. Touch unresponsive at sample rates <=100 kSa/s long memory [p98 #2442].
- Atlan: sample rate can be changed in ACQ menu for longer capture; single-mode sample-rate switching bug fixed in v0.025j/o [p95 #2366, p98 #2436].

## 8. Recovery / bricking incidents
- Zombie47: bootloader flash error ("Device write Access denied", sectors overlapping MBR) fixed by deleting partition, single FAT32 volume [p102 #2537-#2538].
- Cadstar70: FEL mode after turning off menu; fixed by formatting SD (Raspberry Pi) / editing boot byte [p108-p109].
- Two FPGA-flash uploads killed the scope, recovered by reflashing (Atlan) [p115].
- Wrong firmware does not brick hardware (display shifted, TP swapped) [p109 #2717].

## 9. Ideas / wishes not implemented

## 10. Open questions / contradictions
- DC-shift default parameter 1: 112 (Atlan #2294/#2299) vs 116 (#2290); later "basic value around 170" [p97 #2412].
- Boot-mode byte: "byte 32" vs "byte 31" of sector 710 [p96 vs p97]; likely 1- vs 0-based.
- I2C capacitor: 20 pF NP0 0603 (Sleo, desoldered) vs 2.2 nF (in-circuit readings, Russell, later repeated) [p96, p106].
- Chip marking 2515 vs 2415 near ADC/FPGA [p107].
- Battery capacity 4.5 Ah (measured) vs 6000 mAh (website) [p112, p114].
- Sample memory 3000 vs 1500 used vs 4 KB per channel [p95, p99, p111].
- Bandwidth: 20 vs 30 vs 100 MHz; sample rate 200 MSa/s vs "1 GSa/s".
- Which FPGA is on which PCB: unclear which board revisions use EF2 with no external flash; EF2 read-protection unknown [p100, p115].
- Atlan says Sleo/PC implemented FEL on 1014D and ported; pcprogrammer credited with bootloader [p97 #2402 vs p91 #2270] (naming "PC"/"PECO" refers to pcprogrammer).
- Whether new FNIRSI firmware (Sep 2024) fixed anything is unknown; pcprogrammer will not decompile it [p108 #2680].
- "50% button" semantics (trigger vs vertical position) debated, unresolved [p116].
- Extraction caveat: all facts come via an LLM fetcher; verify addresses/values from originals.
