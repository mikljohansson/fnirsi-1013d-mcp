A maintenance release of the open firmware and MCP server for the FNIRSI 1013D (Anlogic AL3A10 variant), from a day of
real measurements by an AI agent on a power board. It needs the same FPGA bitstream as 0.3.0 to 0.3.2, **0x153F**, so
you only update the firmware on the card. Your calibration stays valid.

Documentation: <https://mikljohansson.github.io/fnirsi-1013d-mcp/> (install guide, the screens, the agent guide). The
0.3.0 notes describe everything this firmware does: <https://github.com/mikljohansson/fnirsi-1013d-mcp/releases/tag/v0.3.0>.

### What changed

- **The screen's times are right when a computer chooses the sample rate.** The MCP server can set a sample rate that
  is not the one selected on the scope. Up to 0.3.2 the screen still measured such captures, and the scope's own
  captures while that rate was in force, with the rate selected on the scope: a 483 kHz ripple captured at 200 MSa/s
  under a 500 kSa/s setting read 824 us between peaks. Now the ACQ chip shows the rate the capture was really taken at
  and what one division of the drawn trace lasts (for example 200MSa/s and 500ns/div), and the time cursors, the
  Freq / Period / Width cards, the spectrum view and saved waveforms use the real times. The same ripple reads 2.06 us.
- **An armed single shot survives what happens at the scope.** An agent can arm a single capture, hand over to the
  person ("pull the lead now") and come back later. Up to 0.3.2 the capture was lost as soon as the scope armed again,
  for instance when the person pressed RUN: the agent got "UI capture running" or "ring overwritten". The firmware now
  keeps the computer's last single capture until the computer arms again, whatever is pressed at the scope meanwhile,
  and `scope_fetch_waveform` returns it. When the capture on screen can no longer be read raw, the tool returns the
  trace the screen draws, with a note, instead of failing.
- **MCP server, smaller answers.** `scope_capture` and `scope_fetch_waveform` take `preview_points` (0 = no inline
  waveform: a two-channel answer drops from 17 kB to 2 kB); `scope_status` is compact by default (`detail=true` gives
  the battery and link statistics as before). `window` now selects what the statistics cover; the file always holds the
  whole record.
- **MCP server, measuring events.** New tool `scope_wait_for_event`: set an edge trigger, arm and wait up to an hour
  for an event a person causes, and get the statistics, the file and the times at which the signal crossed the levels
  you name. `scope_measure` has the same level crossings as an item (`crossings`: levels, edge, smoothing, the time
  between two levels) and can work on a saved file.
- **MCP server, frequency of noisy signals.** The frequency of a ripple with switching spikes came back empty or, at
  some sample rates, several percent high, because the spikes add level crossings. When the crossings are uneven the
  tools now report the strongest line of the record's spectrum and say so (`frequency_method` `fft_peak`).

Bench record (`docs/hardware-status.md`, 2026-11-12): on the owner's unit, cursors at a fixed spacing read 824 us at
the scope's own 500 kSa/s, 20.6 us at 20 MSa/s and 2.06 us at 200 MSa/s; a single shot armed by the agent was read
back, all 16382 samples of both channels equal, after RUN and STOP at the scope; `scope_wait_for_event` caught a supply
lead being pulled and returned the three level crossings an agent had computed by hand that morning.

### Update from 0.3.0, 0.3.1 or 0.3.2

1. Download `fnirsi_1013d-fw-0.3.3.bin` and `SHA256SUMS`, and check: `sha256sum -c SHA256SUMS --ignore-missing`.
2. Write the firmware to the card. With the MCP package: `fnirsi1013d-flash --image fnirsi_1013d-fw-0.3.3.bin
   --sha256 <hash> --persist` (it backs up the sectors it replaces). Or build the SD parts and write only the scope part
   with the SD tools, as the install guide describes. The bitstream stays 0x153F: no programmer needed.
3. Coming from 0.3.0, run the calibration wizard for 0.3.1's zero correction: both probes unplugged from the inputs and
   USB unplugged for the zero step, then each probe at x1 on the calibration post. From 0.3.1 or 0.3.2 nothing is needed.
4. MCP: install the attached wheel (`uv tool install <URL of the .whl>`), then start a new session in your agent
   client. A client that only reconnects to the server may keep the old descriptions of the tools and not offer the new
   parameters.

A new install follows the 0.3.0 steps with the 0.3.3 firmware file: <https://mikljohansson.github.io/fnirsi-1013d-mcp/guide/install/>.

### Known issues

- **`scope_status` answers less by default.** A script that read the battery, the bitstream features or the link
  statistics from it must now pass `detail=true`.
- **Not every new option was tried on the scope.** `preview_points`, `scope_fetch_waveform(capture='host')`, the
  `crossings` item of `scope_measure`, the corrected frequency of the ripple and a `scope_wait_for_event` longer than a
  minute were tested on the simulator only. How long a tool call may wait is also set by your agent client; some stop
  at 60 s.
- **A trace read again after the sample rate changed** (`scope_fetch_waveform(processed=true)` of an older computer
  capture) is rebuilt with the present rate. Capture again instead.
- **Probe ground is not USB ground.** The probe ground clips sit on an internal reference about 1.24 V above the
  scope's USB ground. If the device you measure shares the PC's USB ground and a ground clip is on it, every trace
  shifts by about -1.2 V. Power the device from a battery or through a USB isolator, or leave the clip off for slow
  signals (`docs/agent-measurement-guide.md`).
- **One unit.** Everything was benched on a single AL3A10 unit. The gains measured on one range are applied to all six
  ranges; they stayed within 2 % in a check against a lab supply at four ranges.
- **External trigger, not benched with an outside source**: tested only in a loopback through the scope's own
  generator (an outside source must be 3.3 V logic referenced to the USB ground).
- **CH2 code errors at 200 MSa/s with Filter Off**, **a small zero offset at full rate** (about 0.4 code on CH1), the
  **Frequency response** limits, the **USB cable** sensitivity and the other items listed for 0.3.1 are unchanged:
  <https://github.com/mikljohansson/fnirsi-1013d-mcp/releases/tag/v0.3.1>.
- **The firmware runs only with bitstream 0x153F**; other bitstreams show a banner.
