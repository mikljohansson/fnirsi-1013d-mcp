A patch release of the open firmware and MCP server for the FNIRSI 1013D (Anlogic AL3A10 variant): a fix for the first
issue reported on GitHub, and AUTO SET for agents. It needs the same FPGA bitstream as 0.3.0 to 0.3.4, **0x153F**, so
you only update the firmware on the card. Your calibration stays valid.

Documentation: <https://mikljohansson.github.io/fnirsi-1013d-mcp/> (install guide, the screens, the agent guide). The
0.3.0 notes describe everything this firmware does: <https://github.com/mikljohansson/fnirsi-1013d-mcp/releases/tag/v0.3.0>.

### What changed

- **AUTO SET no longer strands you at 20 ns/div.** On a signal of about 10 MHz or more, AUTO SET chose 20 ns/div. That
  is a time/div the scope does not otherwise offer: at 200 MSa/s it holds only four samples per division, and the
  firmware keeps at least ten so the trace is drawn from real samples. So after one tap to zoom out to 50 ns/div there
  was no way back, by tapping or from the ACQ menu, until AUTO SET was pressed again. AUTO SET now ends at the fastest
  time/div the scope offers, 50 ns/div at 200 MSa/s (a 10 MHz signal shows two divisions per period), and zooming out
  and back in works as everywhere else. At slower time/divs AUTO SET now also picks the same sample rate a tap zoom to
  that time/div would, which is sometimes one step faster than before. Thanks to andrewpono for the report
  (<https://github.com/mikljohansson/fnirsi-1013d-mcp/issues/2>).

- **An agent can press AUTO SET.** The MCP server has a new tool, `scope_auto_set`: the scope picks V/div, the trigger
  level and the time/div from the signal, exactly as its AUTO SET button does, and the agent gets the settings it
  chose. Handy as a first step on an unknown signal. It needs this firmware (protocol 1.31); with older firmware the
  tool says so.

### Update from 0.3.0 to 0.3.4

1. Download `fnirsi_1013d-fw-0.3.5.bin` and `SHA256SUMS`, and check: `sha256sum -c SHA256SUMS --ignore-missing`.
2. Write the firmware to the card. With the MCP package: `fnirsi1013d-flash --image fnirsi_1013d-fw-0.3.5.bin
   --sha256 <hash> --persist` (it backs up the sectors it replaces). Or build the SD parts and write only the scope part
   with the SD tools, as the install guide describes. The bitstream stays 0x153F: no programmer needed.
3. Coming from 0.3.0, run the calibration wizard for 0.3.1's zero correction: both probes unplugged from the inputs and
   USB unplugged for the zero step, then each probe at x1 on the calibration post. From 0.3.1 or later nothing is needed.
4. MCP: install the attached wheel (`uv tool install <URL of the .whl>`) and restart your agent's MCP server to get
   `scope_auto_set`. The other tools are unchanged.

A new install follows the 0.3.0 steps with the 0.3.5 firmware file: <https://mikljohansson.github.io/fnirsi-1013d-mcp/guide/install/>.

### Known issues

- **20, 10 and 5 ns/div are not available.** They show grey in the ACQ menu. The scope samples at 200 MSa/s, so they
  would only stretch a handful of samples across the screen; 50 ns/div is the fastest time/div.
- **Probe ground is not USB ground.** The probe ground clips sit on an internal reference about 1.24 V above the
  scope's USB ground. If the device you measure shares the PC's USB ground and a ground clip is on it, every trace
  shifts by about -1.2 V. Power the device from a battery or through a USB isolator, or leave the clip off for slow
  signals (`docs/agent-measurement-guide.md`).
- **One unit.** Everything was benched on a single AL3A10 unit.
- The other items listed for 0.3.4, 0.3.3 and 0.3.1 are unchanged:
  <https://github.com/mikljohansson/fnirsi-1013d-mcp/releases/tag/v0.3.4>.
- **The firmware runs only with bitstream 0x153F**; other bitstreams show a banner.
