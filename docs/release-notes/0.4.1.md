A patch release of the open firmware and MCP server for the FNIRSI 1013D (Anlogic AL3A10 variant): the trigger point
now sits on its marker at the fast time bases, the measurement cards use the whole row, and an agent can set them. It
needs the same FPGA bitstream as 0.3.0 to 0.4.0, **0x153F**, so you only update the firmware on the card. Your
calibration stays valid.

Documentation: <https://mikljohansson.github.io/fnirsi-1013d-mcp/> (install guide, the screens, the agent guide). The
0.3.0 notes describe everything this firmware does: <https://github.com/mikljohansson/fnirsi-1013d-mcp/releases/tag/v0.3.0>.

### What changed

- **The trigger point is where the H marker points.** The place where the signal crosses the trigger level was drawn
  a few samples to the right of the H marker. At ordinary time bases that is a pixel or two and nobody saw it. At
  50 ns/div it was up to 15 pixels, and at the new 10 ns/div it was 20 to 100 pixels, up to two divisions. The scope
  now works out where between two samples the level is crossed and draws that point on the tip of the marker, at
  every time base. Measured on the bench at 10 ns/div: 38 to 68 pixels off before, within 8 pixels (1.6 ns) now.
  Thanks to andrewpono for the report (<https://github.com/mikljohansson/fnirsi-1013d-mcp/issues/3>).
- **Measurement cards use the whole row.** The row under the trace has six places. A channel that is on alone now
  gets all six, whichever channel it is (CH2 alone had three). With both channels on, a channel with more than three
  cards takes the places the other one leaves free.
- **"+N more" opens the rest.** Tap the "+N more" card (or any card of that channel) and every chosen measurement
  shows, in rows stacked upward over the bottom of the trace. Tap "Show less" or any of the cards to fold them
  again. Before, the card only counted. A tap on a card also no longer changes V/div or the time base behind it.
  Thanks to andrewpono for this report too (<https://github.com/mikljohansson/fnirsi-1013d-mcp/issues/4>).
- **An agent can set the cards.** The MCP server has a new tool, `scope_measures`: it reads which measurements are on
  the screen and can choose and order them per channel, so an agent can put the readings that matter for the job in
  front of you and say why. It only changes what the screen shows. It needs this firmware (protocol 1.32); with older
  firmware the tool says so.

### Update from 0.3.0 to 0.4.0

1. Download `fnirsi_1013d-fw-0.4.1.bin` and `SHA256SUMS`, and check: `sha256sum -c SHA256SUMS --ignore-missing`.
2. Write the firmware to the card. With the MCP package: `fnirsi1013d-flash --image fnirsi_1013d-fw-0.4.1.bin
   --sha256 <hash> --persist` (it backs up the sectors it replaces). Or build the SD parts and write only the scope part
   with the SD tools, as the install guide describes. The bitstream stays 0x153F: no programmer needed.
3. Coming from 0.3.0, run the calibration wizard for 0.3.1's zero correction: both probes unplugged from the inputs and
   USB unplugged for the zero step, then each probe at x1 on the calibration post. From 0.3.1 or later nothing is needed.
4. MCP: install the attached wheel (`uv tool install <URL of the .whl>`) and restart your agent's MCP server to get
   `scope_measures`. The other tools are unchanged.

A new install follows the 0.3.0 steps with the 0.4.1 firmware file: <https://mikljohansson.github.io/fnirsi-1013d-mcp/guide/install/>.

### Known issues

- **A few pixels remain at 10 ns/div.** With the trigger level far from the middle of the trace, the crossing can sit
  up to about 8 pixels (under 2 ns) from the marker: a little early on rising edges, a little late on falling ones.
- **Bars and peak-detect traces, and saved waveforms, still start on a whole sample.** A waveform opened from a file
  can be up to one sample off the marker.
- **The expanded cards are not remembered** across a power cycle, and they cover the bottom of the trace while open.
- **Spectrum and Frequency response: "+N more" is still only a count** there.
- **The trigger fix was checked on CH1** with a 1 MHz square wave, both edges, at 10, 20, 50 and 500 ns/div. CH2 as the
  trigger source and the Dots style were not tried on the bench.
- **Probe ground is not USB ground.** The probe ground clips sit on an internal reference about 1.24 V above the
  scope's USB ground. If the device you measure shares the PC's USB ground and a ground clip is on it, every trace
  shifts by about -1.2 V. Power the device from a battery or through a USB isolator, or leave the clip off for slow
  signals (`docs/agent-measurement-guide.md`).
- **One unit.** Everything was benched on a single AL3A10 unit.
- The other items listed for 0.4.0, 0.3.4, 0.3.3 and 0.3.1 are unchanged:
  <https://github.com/mikljohansson/fnirsi-1013d-mcp/releases/tag/v0.4.0>.
- **The firmware runs only with bitstream 0x153F**; other bitstreams show a banner.
