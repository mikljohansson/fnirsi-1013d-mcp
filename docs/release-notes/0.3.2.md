A maintenance release of the open firmware and MCP server for the FNIRSI 1013D (Anlogic AL3A10 variant). It needs the
same FPGA bitstream as 0.3.0 and 0.3.1, **0x153F**, so you only update the firmware on the card. Your calibration stays
valid.

Documentation: <https://mikljohansson.github.io/fnirsi-1013d-mcp/> (install guide, the screens, the agent guide). The
0.3.0 notes describe everything this firmware does: <https://github.com/mikljohansson/fnirsi-1013d-mcp/releases/tag/v0.3.0>.

### What changed

- **Only the calibration dialog writes calibration data.** Since 0.2.105 the firmware checked every 200 MSa/s capture
  for a garbled ADC core and, when a core was flagged three times in a minute, moved that channel's ADC capture timing
  to another trained setting and saved the move in the calibration sector. On fast signals the check raised false
  alarms: on a 24.576 MHz clock 0.3.1 flagged most captures and moved and saved CH1's setting although the data was
  clean. The automatic move is gone. The check now only reports, in Diagnostics and to the MCP server, and it no longer
  flags a busy signal or a clean fast edge: a 12.5 MHz square at 100 mV/div that 0.3.1 flagged reads "capture clean"
  (0 of 2292 captures flagged on the owner's unit). If 0.3.1 moved your setting, run the calibration wizard once to get
  the trained one back.
- **A generator frequency above 10 MHz no longer resets your settings.** The USB command allows the generator up to
  25 MHz, but the check of the saved settings allowed only 10 MHz, so after such a setting every saved setting fell back
  to the defaults at the next power-on. The menu, the saved-settings check and the USB command now share the 25 MHz
  limit, and the generator menu keeps a stored 12.5 MHz instead of cutting it to 10 MHz.
- **MCP server**: `scope_counter` no longer reports the firmware's saturated frequency field (4.29 MHz) for faster
  signals (`frequency_hz` was always right) and warns when the counter sees only a few ADC codes of swing, where it
  reads unreliably; `scope_health` follows the new check and does not ask for the calibration wizard over a flag 0.3.1
  raised on a busy signal.
- **Releases** are now full GitHub releases (only dry runs are pre-releases) and attach only the bitstream this
  firmware needs.

Bench record (`docs/hardware-status.md`, 2026-11-08 and 2026-11-09): on the owner's unit, with this firmware loaded,
the 12.5 MHz test above flagged nothing over two minutes of continuous 200 MSa/s capture, and the calibration sector was
byte-identical before and after; the generator at 12.5 MHz and every other setting survived a power cycle.

### Update from 0.3.0 or 0.3.1

1. Download `fnirsi_1013d-fw-0.3.2.bin` and `SHA256SUMS`, and check: `sha256sum -c SHA256SUMS --ignore-missing`.
2. Write the firmware to the card. With the MCP package: `fnirsi1013d-flash --image fnirsi_1013d-fw-0.3.2.bin
   --sha256 <hash> --persist` (it backs up the sectors it replaces). Or build the SD parts and write only the scope part
   with the SD tools, as the install guide describes. The bitstream stays 0x153F: no programmer needed.
3. Coming from 0.3.0, run the calibration wizard for 0.3.1's zero correction. Coming from 0.3.1, run it if
   Diagnostics > Calibration says a flagged core was moved: both probes unplugged from the inputs and USB unplugged for
   the zero step, then each probe at x1 on the calibration post.
4. MCP: install the attached wheel (`uv tool install <URL of the .whl>`).

A new install follows the 0.3.0 steps with the 0.3.2 firmware file: <https://mikljohansson.github.io/fnirsi-1013d-mcp/guide/install/>.

### Known issues

- **Probe ground is not USB ground.** The probe ground clips sit on an internal reference about 1.24 V above the
  scope's USB ground. If the device you measure shares the PC's USB ground and a ground clip is on it, every trace
  shifts by about -1.2 V. Power the device from a battery or through a USB isolator, or leave the clip off for slow
  signals (`docs/agent-measurement-guide.md`).
- **One unit.** Everything was benched on a single AL3A10 unit. The gains measured on one range are applied to all six
  ranges; they stayed within 2 % in a check against a lab supply at four ranges.
- **External trigger, not benched with an outside source**: tested only in a loopback through the scope's own
  generator (an outside source must be 3.3 V logic referenced to the USB ground).
- **CH2 code errors at 200 MSa/s with Filter Off**, **a small zero offset at full rate** (about 0.4 code on CH1), the
  **Frequency response** limits, the **USB cable** sensitivity and the other items listed for 0.3.1 are unchanged:
  <https://github.com/mikljohansson/fnirsi-1013d-mcp/releases/tag/v0.3.1>.
- **The firmware runs only with bitstream 0x153F**; other bitstreams show a banner.
