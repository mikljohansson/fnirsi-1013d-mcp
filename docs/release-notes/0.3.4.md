A small maintenance release of the open firmware and MCP server for the FNIRSI 1013D (Anlogic AL3A10 variant), with two
fixes from everyday use of 0.3.3. It needs the same FPGA bitstream as 0.3.0 to 0.3.3, **0x153F**, so you only update the
firmware on the card. Your calibration stays valid.

Documentation: <https://mikljohansson.github.io/fnirsi-1013d-mcp/> (install guide, the screens, the agent guide). The
0.3.0 notes describe everything this firmware does: <https://github.com/mikljohansson/fnirsi-1013d-mcp/releases/tag/v0.3.0>.

### What changed

- **AUTO SET is at the bottom of the right bar.** When single triggering you press RUN over and over, and AUTO SET sat
  right under it: one slip threw the whole setup away. AUTO SET and SAVE WAVE have swapped places on every screen
  (Scope, Spectrum analyser, Frequency response), so the bar now reads CTRL, RUN/STOP, SAVE WAVE, T CURSOR, V CURSOR,
  MEASURES, SAVE PIC, AUTO SET. A slip off RUN now saves a waveform file at worst. The buttons of the saved-waveform
  viewer are where they were.
- **A sample rate chosen by an agent becomes the scope's own.** When an agent set, say, 500 kSa/s while the scope sat at
  200 MSa/s, the captures ran at 500 kSa/s, but the ACQ menu still showed 200 MSa/s and tapping the plot to zoom stepped
  through the time/divs of 200 MSa/s, so zooming seemed to do nothing. Now a rate the ACQ menu offers (200 MSa/s down to
  500 Sa/s in 1-2-5 steps) is taken over by the scope: the ACQ menu shows it, the time/div moves to one that goes with
  it, tap zoom works from there and RUN keeps that rate. A rate the menu does not offer (an odd one such as 66.7 MSa/s)
  still runs as in 0.3.3, with the screen's times scaled to it.

### Update from 0.3.0 to 0.3.3

1. Download `fnirsi_1013d-fw-0.3.4.bin` and `SHA256SUMS`, and check: `sha256sum -c SHA256SUMS --ignore-missing`.
2. Write the firmware to the card. With the MCP package: `fnirsi1013d-flash --image fnirsi_1013d-fw-0.3.4.bin
   --sha256 <hash> --persist` (it backs up the sectors it replaces). Or build the SD parts and write only the scope part
   with the SD tools, as the install guide describes. The bitstream stays 0x153F: no programmer needed.
3. Coming from 0.3.0, run the calibration wizard for 0.3.1's zero correction: both probes unplugged from the inputs and
   USB unplugged for the zero step, then each probe at x1 on the calibration post. From 0.3.1 or later nothing is needed.
4. MCP: install the attached wheel (`uv tool install <URL of the .whl>`). The tools themselves are unchanged, so an
   existing session keeps working.

A new install follows the 0.3.0 steps with the 0.3.4 firmware file: <https://mikljohansson.github.io/fnirsi-1013d-mcp/guide/install/>.

### Known issues

- **Muscle memory.** If you are used to AUTO SET as the third button, it is now SAVE WAVE there. Screenshots in the
  documentation may still show the old order.
- **A rate set by an agent moves your time/div.** That is the point of the second fix, but a script that set a 1-2-5 rate
  by divider and expected the scope's own time/div to stay put will see it change. GET_TIMEBASE then reports the time/div
  index instead of 0xFF.
- **Probe ground is not USB ground.** The probe ground clips sit on an internal reference about 1.24 V above the
  scope's USB ground. If the device you measure shares the PC's USB ground and a ground clip is on it, every trace
  shifts by about -1.2 V. Power the device from a battery or through a USB isolator, or leave the clip off for slow
  signals (`docs/agent-measurement-guide.md`).
- **One unit.** Everything was benched on a single AL3A10 unit.
- The other items listed for 0.3.3 and 0.3.1 are unchanged:
  <https://github.com/mikljohansson/fnirsi-1013d-mcp/releases/tag/v0.3.3>.
- **The firmware runs only with bitstream 0x153F**; other bitstreams show a banner.
