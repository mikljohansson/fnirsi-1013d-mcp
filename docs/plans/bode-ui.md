# Frequency response mode: UI design (the Bode plot screen)

Regenerating the boards: in the coordinating session's scratchpad `gen_ux/`, run `python bode_final.py <dir>` (every Frequency response board), `python bode_icon.py <dir>` (menu icon) and `python boards.py <dir> Spectrum` after `patch_spectrum_slider.py` (the Spectrum slider).
The generators import `common.py`, `boards.py`, `bode.py` and `bode_v2.py` from the same folder; publish `<dir>`'s files to the Design artifact linked below.

The screens of the Frequency response mode, redesigned to follow `docs/ui-guidelines.md` after fw-bode's interim UI
(fw 0.2.66, `firmware/AGENTS.md` section 42). The owner rejected that UI on 2026-10-19 (18:50): it remapped RUN/STOP and
AUTO SET to sweep control and was entered from the generator menu. CTRL kept its meaning in fw 0.2.66: its page
already holds Sweep, Thru and Grid. So the remap to undo is RUN/STOP and AUTO SET only. The owner also found the text on
the plot before the first sweep "rather confusing". This plan is the change list for the implementation batch. The mockups are the Design artifact "1013D Bode mode" (https://claude.ai/artifact/DfydC8HJgnemUw3EHenTGP),
generated by `gen_ux/bode.py` beside the makeover's `common.py` and `boards.py` in the coordinating session's
scratchpad. As with the makeover, they are the design language and the acceptance reference, not a pixel
specification (`docs/plans/ux-makeover.md` section 6c).

Owner decisions this design follows **(owner, 2026-10-19)**:

- The mode is a main-menu row, the third, after Spectrum analyser: eight rows at a 52 px pitch. fw 0.2.68 already
  ships the row as "Bode plot". The owner named the mode **"Frequency response"** (18:55), so the row is renamed.
- The right bar's first page keeps its meanings. RUN/STOP is acquisition run and stop, AUTO SET is the mode's own auto,
  then the cursors, MEASURES and the saves. A slot the mode cannot use is empty.
- Sweep control lives where the mode's parameters live, on the CTRL page and its fold-outs. That includes a clear way
  to run one sweep, and RUN for continuous sweeping.
- Warnings sit top-middle. Readouts are cards chosen through MEASURES. Only the 13, 16 and 24 px bitmap fonts are used.
- The RUN/STOP button shows the action a tap does (fw 0.2.68, guidelines section 3). It reads green "RUN" while
  stopped and red "STOP" while running. The top bar chip shows the state.

Final decisions on this design **(owner, 2026-10-19 evening)**. Where an earlier draft said otherwise, these win:

- **The chart is variant 2's**: one pane with two y axes, magnitude on the left, phase on the right (section 9 E). It
  has **no legend**. The axes carry their units ("dB" on the left, "deg" on the right), and each curve has its axis
  label's colour (magnitude CH2 cyan, phase pink). Variant 1's two panes are superseded.
- **Two flagged frequency cursors, C1 and C2**, which T CURSOR shows and hides. Their readout box sits at the bottom
  left of the pane with a C2-C1 row, exactly as variant 2 drew it. The box may cover part of the response; the owner
  accepts that (section 2).
- **Display fold-out: Overlaid (the default, the chosen chart), Magnitude only, Phase only.** The two-pane layout is
  dropped from the design (section 4.1).
- **Frequency axis Log / Linear**, default Log, as a row in the Display fold-out (section 4.1). Magnitude is always
  dB and phase always degrees; neither is configurable.
- **The instruction before the first sweep** says "calibration post" (section 6).

Names: the mode, its main-menu row and its MEASURES title say "Frequency response". "Bode" stays the internal name:
files, the protocol and the host tool (BODE_CTRL, READ_BODE, `scope_bode_sweep`, `bode_*.c`).

The name's fit in the main menu: "Frequency response" is 18 characters, about 128 px in the 16 px font. The row's label
is centred at x 95, right of the icon, which ends at x 42, inside a button that ends at x 140. One line has about 90 px,
so the name does not fit on one line. Two 16 px lines do fit: "Frequency" (9 characters, about 64 px) over "response"
(8 characters, about 57 px). That is how fw 0.2.68 already draws "Spectrum" over "analyser" (`ui_mm_labels`, line 2
at +17 px in the 35 px button). No 13 px line is needed. The main-menu artboard shows it.

## 1a. Main-menu icon (owner request)

The owner asked for an icon that a filter designer recognises at a glance, replacing fw 0.2.68's two parallel falling
lines. The artboard "Main-menu icon candidates" shows three at 1:1 in the menu row and at 4x on a pixel grid:

- **A, chosen: a low-pass response.** A flat passband, a knee, then a 45 degree line (the -20 dB/decade roll-off),
  over an L frame.
- **B: a band-pass hump.** 45 degree skirts with a three-pixel top. It reads as a peak, but at 25 px it also reads as a
  roof or a spectral line.
- **C: A with the corner marked** by a dotted grey vertical. At 1:1 the mark adds noise and does not help.

A is chosen because the low-pass Bode shape is the textbook picture of a frequency response. It is also the shape the
mode measures first on the bench (the RC low-pass).

**The pixels.** Coordinates are from (MAIN_MENU_XPOS + 15, button top), as `scope_main_menu_wave_icon` uses. The icon
is 1 px with no anti-aliasing, 25 x 22 px (x 0..24, y 8..29).

| Part | Pixels | Colour |
|---|---|---|
| Level axis | x 0, y 8..29 | `UI_MM_AXIS_COLOR` (0x707070), as the Scope icon's axes |
| Frequency axis | y 29, x 0..24 | `UI_MM_AXIS_COLOR` |
| Passband | y 12, x 2..10 | fg |
| Knee | (11, 13), (12, 13): two pixels at half slope, which make the corner read rounded | fg |
| Roll-off | (13, 14) to (24, 25), one pixel per column and row | fg |

fg is the colour `scope_main_menu_item` already sets: white, black while touched, 0x686868 when the row is unavailable.
The axes keep their grey in every state, as the Scope icon's do.

```c
//Frequency response (bode-ui.md 1a, owner): a low-pass magnitude response over an L frame
static void scope_main_menu_bode_icon(uint32 y, uint32 fg)
{
  uint32 x = MAIN_MENU_XPOS + 15;

  display_set_fg_color(UI_MM_AXIS_COLOR);
  display_draw_vert_line(x, y + 8, y + 29);
  display_draw_horz_line(y + 29, x, x + 24);

  display_set_fg_color(fg);
  display_draw_horz_line(y + 12, x + 2, x + 10);
  display_draw_horz_line(y + 13, x + 11, x + 12);
  display_draw_line(x + 13, y + 14, x + 24, y + 25);
}
```

`display_draw_line` at exactly 45 degrees sets one pixel per step, so the roll-off is the twelve pixels of the table.
The call site in `scope_main_menu_item` passes the fg it already computed, as it does for the Scope icon.

## 2. The screen

The chart **(owner)**: one pane over the trace area, two y axes, no legend.

- **Pane**: y 60..396, six divisions of 56 px, x 6..726 (58 px before the slider row came). There are no separate
  magnitude and phase panes any more;
  fw 0.2.66's `MAG_*` / `PH_*` geometry goes.
- **Left axis, magnitude**: labels at x 9 in the magnitude colour (CH2 cyan), the top one with its unit ("10 dB").
- **Right axis, phase**: labels right-aligned at x 723 in the phase colour (`PHASE_COLOR`), the top one with its unit
  ("+135 deg"). Each curve is drawn in its axis label's colour, which is how a reader tells them apart.
- **Frequency axis**: Log (default) with decade lines and 2 and 5 sub-lines, or Linear (section 4.1). Labels sit at
  y 400 in grey.
- **Cards**: at y 426 (`UI_MS_SCOPE_Y`), as in the Scope, between the plot and the slider.
- **Slider row (owner, 2026-10-19 19:40)**: y 452..472, the Scope's record-position slider in the same construction
  (rect 2, 452, 726 x 20; the window a 14 px box at y 455) and the same drag (fw 0.2.64: the window follows the finger).

**The slider: Start..Stop over the sweepable range (owner).**

- **Track**: 1 Hz .. 10 MHz on a log scale, seven decades over the 720 px inside the track (about 103 px per decade)
  **(coordinator, owner to veto)**. That is the Sweep fold-out's full range for Start and Stop, so the window never
  runs off the track. The window spans Start..Stop on the same scale: 5 kHz .. 500 kHz draws x 385..591, the default
  100 Hz .. 1 MHz x 211..622.
- **Drag**: the window follows the finger. Start and Stop move together by whole steps of the 1-2-5 table, the same
  number of steps each. That keeps their ratio exactly when the span is a whole number of decades, and within one step
  otherwise. Both stop at the track ends, so the window never changes width by being pushed.
- **While dragging**: the frequency axis and its labels follow, and points of the current table that fall inside the
  new span stay drawn (they are measurements). Nothing is swept yet.
- **On release, a sweep in progress restarts at the new span.** The point in progress is dropped (`bode_stop(e, 1)`),
  the table is cleared and the sweep starts again from the new Start. RUN keeps repeating at the new span.
- **On release while stopped**, one sweep runs at the new span, as Single sweep does, and the run state goes back to
  STOP at its end. A pan asks for data at the new span, and a stopped table at the old span would no longer match the
  axis.
- **Consequences**: the new span is a screen change, so the host's exact settings stop applying (`host_cfg_valid` = 0).
  A thru for the old span turns stale, and its card and warning say so. Start and Stop are saved in word 219 as from
  the fold-out.
- **During AUTO SET's overview** the window spans the overview's 100 Hz .. 10 MHz (x 211..725), and dragging is
  ignored.

The row costs the pane 12 px (two px per division) and moves the cards up to the Scope's y 426. The C1 / C2 readout box
moves with the pane's bottom, to y 342..394.

**Scales and the top division.** Both axes are chosen from the data, and both keep the top division (y 60..118) free
of data when they can. That division holds the warning line without covering the curves.

- **Magnitude**: 5, 10 or 20 dB per division, the first that holds the data in six divisions. Then the top line rises
  by one division whenever the maximum is less than a division below it and the data still fits. This is a change to
  `axes()`, which today has no headroom. A resonance peak then lands in the second division, not under the warning.
- **Phase**: 45 or 90 degrees per division, the first that holds the data, with the same headroom rule. Wrapped phase
  spans at most 360 degrees. At 90 degrees per division that is four divisions plus one of headroom, so the lane always
  fits. On the tank it reads +135 .. -135 deg.
- **The gridlines are shared.** Both axes divide the same six divisions, so a gridline carries one label on each side.

**Display variants (owner).** Overlaid is the chart above, both curves on both axes, and the default. Magnitude only
and Phase only each draw one curve and only its axis, over the same pane with the same scale rules. There is no
two-pane layout.

**Markers** are unchanged. White triangles mark the -3 dB crossings and the resonance peak on the magnitude curve, and
the phase crossings on the phase curve. The point being measured shows as a dotted grey line. Flagged points are grey,
with no joining line.

**Frequency cursors C1 and C2 (T CURSOR, owner).**

- **Drawing**: two dotted vertical lines in the stock cursor colour (`CURSORS_COLOR`). Each has a flag above the pane,
  24 x 15 px at y 45..60, reading "C1" or "C2" in black. Small squares mark where each cursor meets the two curves.
- **Placement**: T CURSOR shows both, as the Scope's T CURSOR shows two time cursors. They first appear at a third and
  two thirds of the axis, snapped to measured points.
- **Touch**: a flag's hit area is 44 x 44 px, and dragging a flag moves its cursor. A tap or drag in the plot moves the
  nearer cursor (the secondary way, guidelines section 3). Move fast in the top bar sets the drag step, as on every
  plot.
- **Values**: cursors snap to measured points and never interpolate, although `bode_interp` exists. A reading is
  always a measurement.

**Cursor readout (owner: the box at the bottom left, as variant 2 drew it).**

- **Box**: grey, x 10..262, y 342..394, inside the pane's bottom left, the position of the DPOS350P's readout. It shows
  while T CURSOR is on.
- **Overlap**: it may cover part of the response, such as a low skirt or the lowest dB label. The owner accepts that,
  and the cursors can be moved or switched off.
- **Rows**: three 13 px rows at a 16 px pitch: C1, C2 and C2-C1. Each has the name in the cursor colour (the
  difference row in white), the frequency in white, the level in the magnitude colour and the phase in the phase
  colour.
- **Example**: "C1 56.17kHz -7.45dB -60.8deg". The widest row, "C2-C1 33.27kHz -13.67dB -129.2deg", fits in 252 px.
- **Flagged points**: when a cursor's point is flagged, its row shows the reason in grey instead of the phase, such as
  "unsettled", "near floor", "CH2 clipped" or "spliced". The C2-C1 row is grey too. A number from a flagged point never
  looks like a good one.
- **Warnings**: the warning line stays top-middle at y 70 in every state. The readout is at the bottom, so they never
  meet.

**Before the first sweep** the empty pane shows one instruction of two lines, top-middle in the warning-line style,
saying what to connect and what to press (section 6). The full wiring explanation (the 1 kOhm source, H = CH2 / CH1,
passive DUTs only, wiring A and B) belongs in the user guide, not on the plot. Entering the mode never starts a sweep:
the post may be wired to anything. That keeps fw 0.2.66's rule.

### 3.1 Why RUN/STOP means continuous sweeping

In every mode RUN/STOP answers one question: is the instrument acquiring and updating what is shown? In Scope, RUN
re-arms the trigger and redraws, and STOP freezes the last record. In Spectrum, RUN keeps computing spectra. In this
mode the acquisition unit is a sweep, so RUN keeps sweeping and redrawing, and STOP freezes the table. That is the same
meaning, applied to what this mode acquires. It is not a remap.

What fw 0.2.66 got wrong was AUTO SET, which ran one sweep. A single sweep is the mode's single shot, not an auto
setup, and the single shot belongs with the sweep's parameters: Sweep fold-out, Single sweep. The Spectrum mode has
the same pattern, with actions inside fold-outs ("Reset" in Analyse, "Clear" in the phosphor section).

Details that follow from the run-state rule:

- **Single sweep** shows chip RUN and button STOP while it runs. At its end the state goes back to STOP. The chip
  shows the state only; whether the run ends after this sweep is said in the Sweep fold-out's Single sweep row.
  **(fw 0.2.70, owner 20:00: "STOP has no effect" during a single sweep)** The chip never reads WAIT in this mode
  (the trigger mode does not apply), and the cards read "sweeping" until the single sweep's table is complete.
- **STOP during a sweep** clears the run state at once, so the button reads RUN and the chip STOP straight away. The
  engine finishes the capture in progress and the point keeps that capture's result (`bode_stop(e, 0)`); **fw 0.2.70**:
  no re-centring, settle retry or CH2 range change follows a STOP, and a STOP in the pre-scan or a background capture
  ends the sweep there (before, the whole point with its retries and range steps ran on, which could take many
  captures on a bad readout). At 10 Hz one capture can take about a second.
- **A host SET_ACQ_STATE run** starts continuous sweeps, as today. A host sweep started with BODE_CTRL shows RUN through
  `ui_run_view`'s host_busy.

### 3.2 AUTO SET: auto span and range (new firmware)

1. **Overview.** One sweep from 100 Hz to 10 MHz: 20 points, Settle Fast, CH2 range Auto, background capture on, thru
   not applied. The plot shows it on its own axis as it comes in. The Sweep card reads "auto n/20". By the design's
   overhead model (`docs/plans/bode-design.md` 3.7) that is about 2 s; the 15 ms per capture is still to be measured.
2. **The span** is taken from `bode_markers_find` on the overview, then snapped outwards to the 1-2-5 Start and Stop
   steps and clipped to 1 Hz .. 10 MHz:
   - LOWPASS or HIGHPASS with a -3 dB crossing fc: Start <= fc / 10, Stop >= 10 fc. That is two decades centred on
     the corner.
   - RESONANT, or a phase that passes both +45 and -45 deg: f0 is the peak, or else the 0 deg crossing. Start <= f0 / 10
     and Stop >= 10 f0 for Q <= 2. Half a decade either side for Q <= 10. Above that, the tightest step pair holding
     f0 (1 +- 4 / Q).
   - **The sharp-tank rule (fw 0.2.70).** The rule above needs Q, and a band narrower than two point spacings is not
     resolved: its -3 dB crossings interpolate across one gap and Q reads low (the overview's points are 1.8x apart, so
     anything above Q of about 1 is unresolved there). Such a band's Q is taken as at least 1 / (2 ln r) for points r
     apart (and at least 2), its Settle one preset up, and AUTO SET measures it again on finer passes around the f0
     found so far before it sets anything: pass 2 f0 / sqrt(10) .. f0 sqrt(10) (12.9 % apart, Settle Resonant), pass 3
     f0 / 1.1 .. f0 x 1.1 (1.0 % apart, High Q), pass 4 f0 / 1.03 .. f0 x 1.03 (0.3 %, High Q), 20 points each
     (`bode_auto_zoom`). It stops at the first resolved pass; then the rule above applies with the measured Q. A Q 50
     tank resolves on pass 3, Q 160 on pass 4; a sharper band takes pass 4's lower bound. The slider shows each pass's
     span, the Sweep card "auto n/20". On the DUT model: Q 50 at 15.3 kHz reads Q 46 on pass 3 -> 10 kHz .. 20 kHz,
     High Q; Q 8.1 at 50.3 kHz resolves on pass 3 as 8.1 -> 10 kHz .. 200 kHz, Resonant (fw 0.2.69 gave such tanks
     half a decade and Settle Resonant, so a Q 50 tank needed a manual narrower span).
   - Still changing at the overview's low end, meaning the first two valid points differ by more than 1 dB or 5 deg:
     Start becomes 10 Hz.
   - FLAT or NONE: the span is kept. The note reads "No corner from 100 Hz to 10 MHz: span kept" for 5 s.
   - Every point flagged near_floor or low_snr: the span is kept. The warning reads "No response: CH2 tip on the DUT
     output?".
3. **Settle** from Q for a resonance: Normal for Q <= 7, Resonant for Q <= 34, High Q above. Otherwise Normal.
   **CH2 range** becomes Auto. **Points** stay the user's.
4. **Then RUN**, as the Scope's auto setup ends in RUN (`scope_do_auto_setup_*` sets `runstate = 1`). The table and the
   cards come from the first real sweep.
5. Changed Start or Stop makes a thru stale. Its card turns amber and the Thru warning appears.
6. **Cancel**: a second tap during the overview aborts it with `bode_stop(e, 1)`, restores the previous table and
   settings, and returns to STOP. The note reads "Auto set cancelled: settings kept". **fw 0.2.70**: the previous table
   is a copy taken when AUTO SET starts (`bode_snap`: plan, points, settings, state; about 25 KB); STOP, a second tap and
   leaving the mode all give it back; an error during a pass (a timeout, the readout fault) keeps the pass's points
   and shows its warning instead.

Implementation: a pure `bode_auto_span(const bode_markers *, overview points, &start_i, &stop_i, &settle)` in
`bode_dsp.c`, host-tested in `host_tests/test_bode.py`, plus a state in `bode_view_autoset` / `bode_view_service`.

### 3.3 SAVE WAVE: the sweep table (new firmware)

SAVE WAVE writes `bode/FR00001.CSV`: a new folder, numbered as the diagnostics report numbers its files
(`pc_save_report`, FA_CREATE_NEW). The file message names it, as SAVE PIC's message does.

- **Header lines**: `#` comments with the firmware version, the bitstream, Start, Stop, Points, Settle, CH2 range,
  thru (none / applied / stale) and the sweep's elapsed ms.
- **One row per point**: `f_hz,mag_db,phase_deg,v1_db,v2_db,range1,range2,flags`. These are READ_BODE's fields
  (protocol row 60), with flags as the host's flag names joined by `|`.
- **No points yet**: the warning reads "Nothing to save: run a sweep first".

Today SAVE WAVE in this mode calls `scope_save_view_item_file(VIEW_TYPE_WAVEFORM)` and saves the scope's last raw
record, which means nothing here.

## 4. Right bar, CTRL page

The guideline order is Display, the mode's analysis controls, Grid, the steppers, then 50 % TRIG.

| Slot (y) | Button | Value shown | Opens |
|---|---|---|---|
| 5 | CTRL (highlighted) | | back to the first page |
| 65 | Display | Overlay, Mag, Phase | Display fold-out |
| 125 | Sweep | the points ("100 pt") | Sweep fold-out |
| 185 | Thru | None, On, Off, Stale, Meas. (as today) | Thru fold-out |
| 245 | Trace style (fw 0.2.70) | Lines, Dots | Trace style fold-out: two rows, as the Scope's |

| 360..416 | empty | | |

**The steppers stay empty.** The sweep ranges CH1 itself at every sweep's pre-scan, and CH2 too in Auto. A CH1 stepper
would change nothing, and a CH2 stepper would only matter with CH2 range Hold, and then only at the next sweep. A
stepper whose effect depends on a fold-out setting, and shows only after a sweep, is a control that seems to do
nothing. The Hold range belongs to the channel's own home, the CH2 chip's menu, which sets the same
`displayvoltperdiv`. There are no volts on any axis here.

**50 % TRIG stays empty.** A sweep's captures use the FPGA auto mode with no trigger level.

**Trace style (owner, 2026-10-19 20:50; fw 0.2.70).** The Scope's button ("Trace" / "style" / the value) and fold-out
(choice rows without icons): Lines (default) joins each curve's valid points in its axis colour; Dots leaves them loose.
Flagged points are grey loose dots in both, so a point that does not count never looks joined. It is how the plot is
shown, so it sits with the analysis controls before Grid (guideline order); saved in settings word 216 (0xB200 | bit 0).

### 4.1 Display fold-out

Three variant rows with icons, the chosen one green, as in Scope and Spectrum **(owner)**:

- **Overlaid** (two curves in one box, one dotted): the default, the chosen chart. The button reads "Overlay": 7
  characters, about 47 px in 13 px, in the 51 px button.
- **Magnitude only** (a flat line that rolls off).
- **Phase only** (a dotted falling S).

Then a separator, and **Frequency axis**, Log or Linear, default Log **(owner)**. A tap toggles it. The row sits in
Display because it is how the plot is shown, and the guideline puts a variant's own parameters inside the Display
fold-out. Spectrum's Scale and Ref level are in Analyse, but they set the level axis of a computed spectrum; there is
no analysis fold-out that holds this one.

The axis setting is display only: the sweep's points stay log-spaced (bode-design 3.1). On a Linear axis over a wide
span they bunch at the left. Over the narrow spans that call for a linear axis, such as 20 .. 100 kHz around a tank,
log and linear spacing differ by little. The Linear axis has labels at 1-2-5 steps of the span.

New firmware: the overlaid chart and the single-curve variants, plus three bits in settings word 220. That word holds
0xB100 | settle | CH2 range << 2. Bits 3..4 take the variant, bit 5 the cursors (section 8) and bit 6 the frequency
axis.

### 4.3 Thru fold-out

The title is "Thru: both tips on the input". The rows:

- **Measure thru** (action): one thru sweep with the warning "Thru sweep: both probe tips on the DUT input". It
  closes the panel.
- **Apply** (switch): its second grey line says "matches this sweep", "other sweep settings" or "none measured". It is
  dimmed while nothing is measured.
- **Clear** (action): forgets the thru, which lives in RAM only. No confirmation: the guideline's destructive rule
  covers stored data, and a thru is redone in one sweep.

This is unchanged from fw 0.2.66. Switch rows are drawn as `ctrl_page.c` draws them.

## 7. Top bar in this mode

- **ACQ chip** reads "Set by" over "the sweep". Its dropdown opens with one line, "The sweep sets the sample rate for

## 9. Adversarial self-review

### A. Against the guidelines

1. **Fixed slot meanings.** Every first-page slot keeps its meaning or is empty. RUN/STOP is the mode's acquisition,
   argued in section 3.1. AUTO SET is the mode's own auto. Pass.
2. **Actions on the CTRL page.** Single sweep and Measure thru are actions inside fold-outs, while the guideline puts
   actions on the first page. Precedent: Spectrum's Reset and the phosphor section's Clear. The owner asked for sweep
   control on the CTRL page. Accepted, and stated here so it is not mistaken for drift.
3. **CTRL page geometry.** Grid sits at y 245 here and at y 185 in Scope and Spectrum, because this mode has two
   analysis controls and the order rule puts them before Grid. The order rule wins, but a user who taps the Grid slot
   by position hits Thru. Owner question 1.
4. **Empty slots.** V CURSOR, the steppers and 50 % TRIG are empty, each with a reason (sections 3, 4). A level cursor
   (a horizontal dB line reading where the response crosses it) is plausible later. It would duplicate the -3dB and
   Level cards for the common cases, so it is roadmap, not a placeholder.
5. **Card block colours.** The guideline allows the channel colour or neutral grey. Magnitude cards use CH2 cyan, the
   magnitude trace's colour: H is CH2's response over CH1, and fw 0.2.66 draws it so. Phase cards use the phase
   trace's pink, a colour outside the rule. The alternative, all neutral, loses the card-to-trace link. Owner
   question 2.
6. **Colour with words.** Thru's state is a word in a colour ("applied" green, "stale" amber). Flagged points are grey
   on the plot, and the cursor readout names the flag. Pass.
7. **Fonts and widths.** Only 13 and 16 px are used. Every line is
   budgeted at 6.7 / 7.1 px per character. Warnings are capped at 50 characters (section 6). The cursor readout is
   checked at its widest row, "C2-C1 33.27kHz -13.67dB -129.2deg", inside its 252 px box. The instruction's 69
   characters (490 px) fit the 720 px pane. Pass.
8. **Touch.** Fold-out rows are 44 px. The - / + keys are 30 px drawn, but a tap acts by row half, so each target is
   about 95 x 44 px. The cursor handle's hit area is 44 x 44. Pass.
9. **Warnings.** fw 0.2.66 had texts without an action and texts up to 86 characters. Section 6 fixes both.
10. **Every unavailable state has defined text.** "no sweep", "sweeping", "not found", "not run", "none". The grey
    main-menu row had no text; section 6 adds the reason on tap. That row stays grey: the guideline's "no greyed
    rows" is about unbuilt features, and this row is a built one the hardware cannot run.
11. **Nothing shown that the firmware does not have.** Every value comes from `bode_markers`, READ_BODE or
    `bode_estimate_ms`. The new functions are auto span, the CSV, the Display variants, the MEASURES list and the
    cursor toggle. Section 8 lists them as firmware work, and the mockups draw nothing beyond them.

### B. Against fw-bode (section 42): functions lost or moved

1. **One-tap single sweep (AUTO SET) is gone.** A single sweep is now CTRL, Sweep, Single sweep: three taps, and the bar
   stays on the CTRL page. RUN then STOP gives repeated sweeps in two taps. AUTO SET now gives the most useful one-tap
   result: a span found and sweeping. Accepted.
2. **Tap-anywhere cursor.** It needs T CURSOR first. The cursor state is saved, so a user who wants it once has it from
   then on. Accepted.
3. **Shape-driven cards.** fw 0.2.66 chose -3dB, or Peak and Q, by the shape found. The fixed defaults show "not found"
   for Peak and Q on a low-pass. Consistency with MEASURES in the other modes wins, and the text says why. Owner
   question 4.
4. **The Thru card** appeared only while a thru was applied. It is now a default card that reads "none" or "off". One
   card place is used even when nobody uses the thru. Accepted: a thru silently applied is the bigger risk.
5. **"Stop sweep" in the fold-out.** It is gone; STOP on the first page does it. Nothing lost.
6. **Host settings precedence** (`host_cfg_valid`) is unchanged. AUTO SET's results count as a screen change, so the
   screen's values apply again. That matches the rule for the fold-out rows.

### C. Values and feasibility

1. **AUTO SET's duration** (about 2 s) rests on the unmeasured 15 ms per capture. Below 100 Hz the overview does not
   look. A corner under 100 Hz is only detected as "still changing", which sets Start to 10 Hz. The next sweep then
   takes tens of seconds at 50 points (bode-design 3.7). The Single sweep row's estimate shows that before anyone
   commits.
2. **High-Q tanks** (the owner's metal-detector use) need narrow spans. The 1-2-5 Start and Stop steps allow 20 kHz ..
   100 kHz around 50 kHz at best. That is about 1.6 % point spacing at 100 points, or two to three points inside the
   bandwidth of a Q 23 tank. Finer steps (for example 1, 1.5, 2, 3, 5, 7 per decade, 43 steps) do not fit word 219's
   5-bit fields and need one of words 214..218. Owner question 3.
3. **The free top division** (the warning lane) costs one of six magnitude divisions in the common case. The data keeps five divisions: 50 dB
   at 10 dB per division where today's rule allows 60, and 100 dB at 20 dB per division where it allows 120. A sweep
   spanning 50 to 60 dB therefore moves to 20 dB per division. That is coarser, but the whole trace stays readable.
4. **The "sweeping" rule** hides markers during the first sweep of a new plan. It needs a "complete table" flag that
   resets when the plan changes, which is cheap: every point has p_have since the plan's sweep id.
5. **CSV size**: 100 rows of about 60 bytes, written once. No issue.

### D. Contradictions found and resolved

1. **Readout versus data.** A cursor box at the scope's 88 x 50 px position would have covered a low-pass passband,
   which sits just under the top line. The first mockup render showed the conflict. The final design **(owner)** puts
   the C1 / C2 box at the bottom left as the DPOS350P does and accepts that it may cover part of the response. The
   warning keeps the free top division to itself.
2. **The single sweep's chip.** I first drew a separate "SNGL" chip. fw 0.2.68's `ui_run_view` has three states,
   STOP, RUN and WAIT, and a single sweep is acquiring, so it shows RUN. The once-only part is said where it is chosen.
3. **AUTO SET versus the thru.** Auto changes Start and Stop, so a thru goes stale by its own rule. The amber card and
   warning say so. AUTO SET must not silently drop the thru.
4. **SAVE WAVE's file** is not listed by Saved waveforms, which reads only the scope's own format. Its file message
   names the path, and the file is read on a PC through USB drive. Owner question 5.
